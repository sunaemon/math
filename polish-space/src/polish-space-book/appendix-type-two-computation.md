# Appendix: Input Names and Type-Two Computation {#sec:appendix-type-two-computation}

This appendix extends the numerical lambda calculus of §{sec:appendix-lambda-computability} to computation with
an arbitrary input name. Baire space consists of the functions $\NN\to\NN$, with the product topology obtained
from discrete $\NN$. An input name is supplied as a function argument; it need not be computable or finitely described.

## Relativization and real parameters {#sec:lambda-relativization}

\begin{mathmeta}
  \vars{a,b,p}{Name}
\end{mathmeta}

For a real parameter $a\in\BaireSpace$, identify $a$ with a function $\NN\to\NN$.
\termdefineas{relativization}{Relativization} is the operation of allowing a fixed real parameter as background input. A
\termdefine{program relative to a real} is a lambda program that may use $a$ as an input function and query values
$a(n)$ during evaluation. This replaces the oracle-tape picture by the syntax that better matches later domain theory: a
real parameter is an argument of function type, not a separate machine component.

A real $b\in\BaireSpace$ is \termdefineas{Turing reducibility}{Turing reducible} to $a$, written $b\leq_T a$, if some
lambda program relative to $a$ computes the function $n\mapsto b(n)$. Two reals $a,b$ are
\termdefine{Turing equivalent}, written $a\equiv_T b$, if $a\leq_T b$ and $b\leq_T a$.

## Input names and Type-Two realizers {#sec:lambda-input-realizers}

\begin{mathmeta}
  \vars{m,n}{Nat}
  \vars{p}{Name}
\end{mathmeta}

\begin{definition*}[Input-query computation and realization]
Use the lambda terms modulo alpha-equivalence defined above, with Church numerals $\ChurchNumeral{n}$ as numerical data.
Fix one variable $o$ to stand for the supplied input name. For a name $p:\NN\to\NN$, write $\LambdaInputStep{p}{M}{N}$
for a beta step or an input-query step, with the latter generated by
$$
\LambdaInputStep{p}{o\ChurchNumeral{i}}{\ChurchNumeral{p(i)}}.
$$
Queries may be performed in either part of an application and under an abstraction whose binder differs from $o$. A
binder equal to $o$ shadows the input parameter: occurrences it binds are not queries. Ordinary beta-reduction is still
allowed in every term context. All operations are on alpha-classes. This specifies the behavior of a function argument
within lambda calculus; it introduces no additional program syntax.

A program $\Phi$ is a closed lambda term. Given $p$ and a coordinate $n$, start with $\Phi\,o\,\ChurchNumeral{n}$. Write
$\LambdaInputSteps{p}{M}{N}$ for a finite sequence of beta/query steps, including the empty sequence. We say that $\Phi$
returns $m$ on this input when
$$
\LambdaInputSteps{p}{\Phi\,o\,\ChurchNumeral{n}}{\ChurchNumeral{m}}.
$$
The name $p$ supplies query answers; it is not required to have a finite lambda description. Church numerals admit no
further steps: they are closed beta-normal forms, and a query requires a free occurrence of the input parameter.

A \termuse{Type-Two lambda realizer} for a partial map $\PartialFunctionMap{F}{\BaireSpace}{\BaireSpace}$ is one closed
term $\Phi$ such that, for every $p\in\DomainOf{F}$ and $n,m\in\NN$,
$$
\LambdaInputSteps{p}{\Phi\,o\,\ChurchNumeral{n}}{\ChurchNumeral{m}}
\quad\Longleftrightarrow\quad F(p)(n)=m.
$$
Thus each output coordinate is obtained, and every numeral output has the specified value. No condition is imposed
outside the domain. In particular, the domain may be smaller than the set of names on which all coordinate computations
terminate. The same closed term must work for every valid name and every coordinate; choosing a different term
separately for each name does not suffice. A partial map on names is called computable when it has such a realizer.
\end{definition*}

### Confluence with an input name {#sec:lambda-input-confluence}

\begin{mathmeta}
  \define{ParallelLambdaInput}
\end{mathmeta}

For a fixed name $p$, extend the parallel beta rules of §{sec:lambda-calculus} to a relation
$\ParallelLambdaInput{p}{M}{N}$. Choose every binder in the abstraction and contraction rules different from $o$, and
add the query rule
$$\ParallelLambdaInput{p}{o\ChurchNumeral{i}}{\ChurchNumeral{p(i)}}.$$
The variable and application rules are unchanged. Fresh alpha-renaming makes the binder requirement harmless: every
abstraction has a representative with a binder different from $o$. Induction on the number of nodes, using that variable
renaming preserves this number, proves reflexivity for all alpha-classes.

\begin{theorem*}[\termuseas{input-query confluence theorem}{Confluence with input queries}]
For every name $p$, if $\LambdaInputSteps{p}{M}{N}$ and $\LambdaInputSteps{p}{M}{P}$, there is a term $Q$ such that
$\LambdaInputSteps{p}{N}{Q}$ and $\LambdaInputSteps{p}{P}{Q}$. In particular, two numeral outputs from the same term
have the same natural-number value.
\end{theorem*}

\begin{proof}[Proof]
Parallel reduction introduces no free variables. Its substitution lemma holds for substitution lists that never replace
$o$: if the two lists send each variable to parallel-related terms, their images of parallel-related terms are again
parallel-related. The proof follows the finite-list argument in §{sec:lambda-calculus}, choosing each fresh binder
outside both bodies, both lists' forbidden variables, and $\{o\}$. Prepending a binder renaming still leaves $o$ fixed.
In the new query case, substitution fixes $o$ and both closed numerals, so the same query rule applies. Thus the
substitution lemma needed for beta contraction remains valid, since its binder differs from $o$.

A parallel step is a finite beta/query reduction: reduce the components and then contract the root when required.
Conversely, each beta/query step is parallel. For a beta step under any binder, first choose a fresh binder different
from $o$; the ordinary beta-substitution theorem justifies this renaming even when the original binder was $o$. Since
numerals admit no beta/query steps, a parallel step from a numeral leaves it unchanged.

Now repeat the parallel diamond proof, using fresh binders and the restricted substitution lemma. Only the cases
involving a root query are new. A beta contraction cannot compete with a root query: its operator is an abstraction,
whereas a query's operator is the variable $o$. If the other step retains the application, its operator stays $o$ and
its numeral argument stays unchanged, so that result takes the same query step. If both steps query, injectivity of
Church numerals gives the same queried index and hence the same answer. All other cases join exactly as in the beta
diamond proof. Moving a parallel step across a finite parallel reduction and then iterating this construction joins any
two finite reductions. The equivalence with finite beta/query reduction proves confluence. Numerals are terminal, so any
common reduct of two numeral outputs equals both of them; their injectivity proves equality of the output values.
\end{proof}


Consequently, to verify that a closed term realizes $F$, it suffices to exhibit a reduction to $\ChurchNumeral{F(p)(n)}$
for every valid name $p$ and coordinate $n$. The theorem rules out every other numerical output. For example,
$\lambdaab{a}{a}$ realizes the identity on names: one beta step exposes the query $o\ChurchNumeral{n}$. The term
$\lambdaab{a}{\lambdaab{b}{\ChurchNumeral{m}}}$ realizes the constant name whose every coordinate is $m$: two beta steps
return that numeral. Both terms are closed.

### Head exposure with input queries {#sec:lambda-input-head-exposure}

\begin{mathmeta}
  \define{LambdaInputHeadStep,LambdaInputHeadSteps,LambdaInputStandardSteps}
\end{mathmeta}

To exclude numerical outputs from an endlessly unsuccessful search, we need the head-exposure argument also for input
queries. Fix a name $p$. A \termdefine{head step with input queries}, written $\LambdaInputHeadStep{p}{M}{N}$, is a root
beta contraction, such a head step in the operator of an application, or a grouped query step
$$\frac{\LambdaInputSteps{p}{A}{\ChurchNumeral{n}}}
 {\LambdaInputHeadStep{p}{oA}{\ChurchNumeral{p(n)}}}.$$
The last rule groups a finite reduction of the query argument and one actual query. It is an abbreviation for existing
reductions. Write $\LambdaInputHeadSteps{p}{M}{N}$ for finitely many of these head steps. No head step enters an
abstraction body.

\begin{lemma*}[\termdefineas{input head step determinism}{Determinism of head steps with input queries}]
Every head step is a finite beta/query reduction. If $\LambdaInputHeadStep{p}{M}{N}$ and
$\LambdaInputHeadStep{p}{M}{P}$, then $N=P$.
\end{lemma*}

\begin{proof}[Proof]
Expand a grouped query into its argument reduction followed by the query; lift through the operator context when
necessary. For determinism, inspect the operator. An abstraction permits the root contraction and has no head step of
its own. The input variable permits a grouped query and has no head step of its own. If the query argument reduces to
two numerals, confluence makes their values equal, so both queries give the same answer. In every other case, any head
step comes from the operator, where induction gives uniqueness.
\end{proof}

Use the inductive standard-reduction rules of §{sec:lambda-head-exposure}, replacing their head prefixes by the present
head prefixes. More explicitly, define $\LambdaInputStandardSteps{p}{L}{M}$ by
$$\frac{\LambdaInputHeadSteps{p}{L}{x}}{\LambdaInputStandardSteps{p}{L}{x}},$$
$$\frac{\LambdaInputHeadSteps{p}{L}{AB}\quad
 \LambdaInputStandardSteps{p}{A}{C}\quad\LambdaInputStandardSteps{p}{B}{D}}
 {\LambdaInputStandardSteps{p}{L}{CD}},$$
$$\frac{\LambdaInputHeadSteps{p}{L}{\lambdaab{x}{A}}\quad
 \LambdaInputStandardSteps{p}{A}{B}\quad x\ne o}
 {\LambdaInputStandardSteps{p}{L}{\lambdaab{x}{B}}}.$$
The binder restriction keeps the input variable free during the body reduction; fresh alpha-renaming supplies such a
binder for every abstraction.

\begin{lemma*}[\termdefineas{inductive standard input reduction}{Inductive standard reduction with input queries}]
For all terms $M,N$,
$$\LambdaInputSteps{p}{M}{N}\quad\Longleftrightarrow\quad
\LambdaInputStandardSteps{p}{M}{N}.$$
Consequently, if $M$ reduces to an abstraction, there are $x,A$ such that
$\LambdaInputHeadSteps{p}{M}{\lambdaab{x}{A}}$. In particular, a numerical output implies such a finite head reduction.
\end{lemma*}

\begin{proof}[Proof]
Fresh-binder induction proves reflexivity, and expanding head steps shows that every standard derivation is a finite
beta/query reduction. A head prefix may be prepended to any standard derivation. For the substitution property, use two
finite substitution lists that leave $o$ fixed and relate their images of each variable by standard reduction. Head
prefixes are preserved by either list: root contractions use capture-avoiding substitution, and a grouped query uses the
substitution property for its finite argument reduction, with $o$ and the closed numeral fixed. Induction on a standard
derivation now proves compatibility with the two lists. At an abstraction, rename its binder outside both bodies, both
lists' forbidden variables, and $\{o\}$; prepend this renaming to each list. The old binder differs from $o$, so both
extended lists still preserve the input.

Next show closure under appending one beta/query step. For a root beta contraction, invert the application and
abstraction rules. Their head prefixes expose a root redex; contract it and apply the substitution property to the
related bodies and arguments. For a query, invert the application and variable rules to expose $AB$ with a head
reduction from $A$ to $o$ and a standard reduction from $B$ to the queried numeral. Reduce the operator to $o$ and use
the grouped query rule on $B$. Application contexts use the corresponding subderivation. For an abstraction context,
strengthen the argument to a substitution list and choose a common binder fresh also for the earlier source. This is
possible because finite reductions introduce no free variables. The body induction then lifts through a binder different
from $o$. The same argument handles beta steps originally written with binder $o$ by first renaming that binder.
Induction on a finite reduction proves the forward implication. Finally, invert the last standard rule when the target
is an abstraction: its head prefix gives the required exposure. Every Church numeral is an abstraction.
\end{proof}

\begin{lemma*}[\termdefineas{input head step postponement}{Moving an input head step to the front}]
If $\LambdaInputSteps{p}{L}{M}$ and $\LambdaInputHeadStep{p}{M}{N}$, there is $P$ such that
$\LambdaInputHeadStep{p}{L}{P}$ and $\LambdaInputSteps{p}{P}{N}$.
\end{lemma*}

\begin{proof}[Proof]
Replace the first reduction by a standard derivation and induct on the last head step. A root contraction is handled by
the application and abstraction inversions, followed by substitution, as above. A grouped query is handled by the
application inversion: expose the input variable in the operator, concatenate the argument's standard reduction with its
given reduction to a numeral, and perform the grouped query. In either case this gives a nonempty head prefix from $L$;
remove its first step and finish by finite beta/query reduction. For a head step inside the operator, apply the
induction hypothesis there, lift the resulting step through application, and prepend the existing head prefix. Again
remove its first step and finish both subterm reductions.
\end{proof}

\begin{proposition*}[\termdefineas{infinite input head stages}{Infinite input head stages exclude numerical output}]
Suppose that for every $k$ there is $T_k$ with
$$\LambdaInputHeadStep{p}{S_k}{T_k},\qquad
\LambdaInputSteps{p}{T_k}{S_{k+1}}.$$
Then $S_0$ has no numeral output with input $p$.
\end{proposition*}

\begin{proof}[Proof]
A numeral output would give a finite head reduction to an abstraction. As in §{sec:lambda-head-exposure}, prove the
stronger assertion allowing an initial finite reduction from a term $M$ to $S_0$, and induct on a head reduction from
$M$ to an abstraction. At length zero, moving the first stage's head step to the front would produce a head step from an
abstraction, which is impossible. Otherwise move that step to the front and use determinism to identify its target with
the first target on the chosen head reduction. The shorter head reduction and the shifted sequence $S_1,S_2,\ldots$
contradict the induction hypothesis. This counts grouped head steps; the reductions inside queries need not have a
common length bound.
\end{proof}

### Finite use {#sec:lambda-input-finite-use}

\begin{mathmeta}
  \vars{k}{Nat}
\end{mathmeta}

\begin{lemma*}[Finite use for input-query reductions]
If $\LambdaInputSteps{p}{M}{N}$, there is $k\in\NN$ such that $\LambdaInputSteps{q}{M}{N}$ for every name $q$ satisfying
$q(i)=p(i)$ for all $i<k$. In particular, any numeral output is preserved by agreement on a sufficiently long finite
prefix of the input name.
\end{lemma*}

\begin{proof}[Proof]
A beta step needs no answers from the name. A query at coordinate $i$ is preserved by agreement below $i+1$. Moving
either step into an allowed term context keeps the same bound. Now induct on the length of a finite reduction: the empty
reduction needs no answers, and appending one step requires only the maximum of the bounds for the preceding reduction
and the new step. Every name agreeing on this prefix therefore admits the same reduction to the same final term. This
includes queries whose coordinates depend on earlier answers.
\end{proof}

### Finite certificates with input answers {#sec:lambda-input-certificates}

\begin{mathmeta}
  \define{LambdaQuerySuccessors,LambdaInputSuccessors,LambdaInputCertificate}
  \define{LambdaAnswerTableCode,LambdaInputTest}
  \vars{s}{Nat}
\end{mathmeta}

Finite-use statements describe how an existing computation depends on its input. To search for computations, we also
need finite objects that certify them. An \termdefine{input answer table} is a finite list $t$ of pairs $\Pair{i}{v}$ of
natural numbers. It agrees with a name $p$ if $p(i)=v$ for every pair in the list. Repeated pairs are allowed, and the
table need not be minimal. Agreement rules out conflicting answers at the same address.

Work first with named terms and the fixed named representatives of Church numerals from
§{sec:lambda-program-input-codes}. Form the finite list $\LambdaQuerySuccessors{t}{M}$ recursively. At an application
$AB$, first scan $t$: a pair $\Pair{i}{v}$ contributes $\ChurchNumeral{v}$ exactly when $A$ is literally $o$ and $B$ is
literally the fixed representative of $\ChurchNumeral{i}$. Then append the lists obtained by taking a query step in the
left and right subterms, restoring the other subterm in each case. At an abstraction with binder different from $o$,
restore that binder around each query reduct of the body. At an abstraction binding $o$, and at a variable, the list is
empty. Equality in the root test is syntactic equality of finite named terms.

Combine this list with the ordinary beta reducts:
$$\LambdaInputSuccessors{t}{M}:=
\LambdaBetaSuccessors{M}\mathbin{+\!+}\LambdaQuerySuccessors{t}{M}.$$
Here $+\!+$ denotes list concatenation. Beta steps are still allowed under every binder; only queries are blocked by a
binder equal to $o$. Every list is finite. The chosen traversal order and repeated entries do not affect membership.

\begin{lemma*}[\termdefineas{finite-table input steps}{One-step reductions with finite answer tables}]
If $t$ agrees with $p$ and $N\in\LambdaInputSuccessors{t}{M}$, then $\LambdaInputStep{p}{[M]}{[N]}$. Conversely, every
input-query step between alpha-classes has named representatives $M,N$ and a finite table $t$ agreeing with $p$ such
that $N\in\LambdaInputSuccessors{t}{M}$. Enlarging the table retains all previously listed one-step possibilities.
\end{lemma*}

\begin{proof}[Proof]
Induction on the source term identifies the query list with the query rule and its allowed contexts. At a root query,
agreement supplies the asserted answer from $p$; application contexts and abstractions with binder different from $o$
preserve the step. The beta list already has the corresponding soundness property. For the converse, induct on the
input-query step. A beta step uses raw representatives and the empty table. A root query uses the fixed numeral
representatives and the singleton table containing its address and actual answer. Lift these representatives through
application contexts or an allowed abstraction. Finally, adding table entries preserves root-query membership, hence all
query contexts by induction, while the beta list is unchanged.
\end{proof}

For a table $t$, define the Boolean certificate check $\LambdaInputCertificate{t}{M}{N}{c}$ just as in
§{sec:lambda-reduction-certificates}, using $\LambdaInputSuccessors{t}{A}$ for each listed step. The empty certificate
is accepted exactly when $M$ and $N$ are alpha-equivalent. A certificate beginning with $\Pair{A}{B}$ is accepted
exactly when
$M$ is alpha-equivalent to $A$, the term $B$ belongs to $\LambdaInputSuccessors{t}{A}$, and the remaining certificate is
accepted from $B$ to $N$. All checks on terms and lists are finite. Changes of representative are checked at the joins,
so the use of fixed numeral representatives in root queries loses no reductions.

\begin{proposition*}[\termdefineas{input-query reduction certificates}{Finite certificates for input-query reduction}]
For every name $p$ and named terms $M,N$, the relation $\LambdaInputSteps{p}{[M]}{[N]}$ holds if and only if there are a
finite table $t$ agreeing with $p$ and a finite certificate $c$ such that
$\LambdaInputCertificate{t}{M}{N}{c}=\mathrm{true}$.
\end{proposition*}

\begin{proof}[Proof]
For soundness, induct on an accepted certificate. The empty case gives equality of alpha-classes. Otherwise, its first
pair gives a valid input-query step by the lemma, and the induction hypothesis supplies the rest of the reduction.

Conversely, induct on a finite input-query reduction, keeping arbitrary named representatives of its endpoints. For an
empty reduction, use the empty table and certificate. For the first step of a nonempty reduction, take the
representatives and table supplied by the lemma. Apply the induction hypothesis to the tail, starting with the chosen
target representative of that first step. Concatenate the two answer tables. Both agree with $p$, so their concatenation
does too. Table enlargement preserves the first step and every step of the tail certificate. Prepend the first pair to
the tail certificate; alpha-equivalence at the join handles the chosen source representative.
\end{proof}

Encode an answer table by the existing numerical list and pairing codes:
$$\begin{aligned}
&\LambdaAnswerTableCode{[\Pair{i_0}{v_0},\ldots,\Pair{i_{r-1}}{v_{r-1}}]}\\
&\qquad :=\LambdaListCode{[\NatPair{i_0}{v_0},\ldots,\NatPair{i_{r-1}}{v_{r-1}}]}.
\end{aligned}$$
Decode a number as a list and unpair each entry. The list and pairing identities show that encoding and decoding are
mutual inverses. A candidate code $e$ is a pair of an answer-table code and a certificate code; write $t_e,c_e$ for the
decoded objects. Check the finitely many equations $p(i)=v$ in $t_e$ and the finite test
$\LambdaInputCertificate{t_e}{M}{N}{c_e}$. Define $\LambdaInputTest{p}{s}{M}{N}$ to be true exactly when at least one
candidate code $e<s$ passes both checks.

\begin{corollary*}[\termdefineas{finite-stage input-query detection}{Finite-stage detection with input queries}]
Each stage uses only finitely many queries to $p$. Once a stage accepts, every larger stage accepts, and
$$\LambdaInputSteps{p}{[M]}{[N]}\quad\Longleftrightarrow\quad
\exists s\in\NN\;\LambdaInputTest{p}{s}{M}{N}=\mathrm{true}.$$
For a closed named program $P$, taking $M=P\,o\,\ChurchNumeral{n}$ and $N=\ChurchNumeral{m}$ gives an exact finite-stage
criterion for output $m$ at coordinate $n$.
\end{corollary*}

\begin{proof}[Proof]
Only finitely many candidate codes occur at a fixed stage, and each decoded table and certificate is finite. Increasing
the stage retains every earlier candidate. If a candidate is accepted, its consistent table and valid certificate give
the reduction by the proposition. Conversely, encode a table and certificate for an existing reduction, pair their
codes, and choose a stage larger than that pair code. Decoding recovers the same witnesses, so the candidate is accepted
at that stage. The final assertion is the definition of a program's numerical output.
\end{proof}

\begin{lemma*}[\termdefineas{bounded input-test finite use}{A uniform input bound for each test stage}]
For tables and stages define
$$\begin{aligned}
K([])&:=0,& K(\Pair{i}{v}::t)&:=\max(i+1,K(t)),\\
H(0)&:=0,& H(s+1)&:=\max(H(s),K(t_s)).
\end{aligned}$$
If $q(i)=p(i)$ for all $i<H(s)$, then
$$\LambdaInputTest{q}{s}{M}{N}=\LambdaInputTest{p}{s}{M}{N}.$$
The bound depends only on the stage, not on the input name or endpoint terms.
\end{lemma*}

\begin{proof}[Proof]
Induction on a table shows that agreement below $K(t)$ preserves the truth of all its answer checks. The certificate
check itself does not use the name. Now induct on the stage. Stage zero checks no candidates. Passing from stage $s$ to
stage $s+1$ retains the earlier candidates and adds just candidate $s$. The two bounds in the maximum preserve the
earlier result and the new candidate's answer check, respectively. Hence the Boolean result of the whole stage is
unchanged, whether it is true or false.
\end{proof}

### The stage number bounds the input addresses {#sec:lambda-stage-address-bound}

\begin{mathmeta}
  \vars{d,i,v}{Nat}
\end{mathmeta}

\begin{lemma*}[\termdefineas{stage address bound}{Stage address bound}]
With the paired-successor list coding, $K(t)\le\LambdaAnswerTableCode{t}$ and $H(s)\le s$.
Consequently, agreement of two input names below $s$ suffices for their stage-$s$ tests to agree.
\end{lemma*}

\begin{proof}[Proof]
The empty table has bound and code zero. If its first entry is $\Pair{i}{v}$ and its tail has code $d$,
its code is $\NatPair{\NatPair{i}{v}}{d}+1$. Each numerical projection is at most the paired number.
Thus $i+1$ is at most this code, and the induction hypothesis bounds the tail's addresses by $d$,
which is smaller than the whole code. Taking the maximum proves the table inequality.
The table code of candidate $s$ is at most $s$. Induction in
$H(s+1)=\max(H(s),K(t_s))$ therefore gives $H(s+1)\le s+1$.
Apply the preceding input-agreement lemma with this bound.
\end{proof}

### Programs for finite-table certificates {#sec:lambda-input-certificate-programs}

\begin{mathmeta}
  \define{LambdaSyntaxRecursor,LambdaRootQueryProgram,LambdaQueryReductListCode}
  \define{LambdaQueryReductProgram,LambdaInputReductProgram,LambdaInputStepTest,LambdaInputCertificateCheck}
\end{mathmeta}

We implement the finite-table reduction tests by closed lambda terms. At this stage the answer table is numerical data:
the programs inspect the stored pairs without querying any input name. Agreement of these stored answers with the actual
name is the separate finite check in §{sec:lambda-input-certificates}. Choose the distinguished input variable to be
$o=x_0$, whose syntax code is zero. All other syntax codes are positive.

To supply the application handler with a table at run time, expose the three syntax-fold handlers as arguments:
$$\LambdaSyntaxRecursor:=\lambdaab{v}{\lambdaab{a}{\lambdaab{l}{\LambdaSyntaxFold{v}{a}{l}}}}.$$
Expand the fold inside the abstractions, choosing its internal binders distinct from the three parameters. The result is
closed. For closed handlers, three beta steps supply them to precisely the fold of §{sec:lambda-syntax-recursion}.

For a root query, scan the table by list recursion. Define the abbreviations and closed programs
$$\begin{aligned}
K(b,i,v,r)&:=\LambdaZeroTest\,(\LambdaEqual\,b\,(\LambdaNumeralCodeProgram\,i))\,r\\
 &\quad(\LambdaListCons\,(\LambdaNumeralCodeProgram\,v)\,r),\\
H_q&:=\lambdaab{b}{\lambdaab{c}{\lambdaab{r}{
 K(b,\LambdaNumericProjection{1}\,c,\LambdaNumericProjection{2}\,c,r)}}},\\
R(t,b)&:=\LambdaListRecursor\,(H_qb)\,\ChurchNumeral{0}\,t,\\
\LambdaRootQueryProgram&:=\lambdaab{t}{\lambdaab{a}{\lambdaab{b}{
 \LambdaZeroTest\,a\,R(t,b)\,\ChurchNumeral{0}}}}.
\end{aligned}$$
Expand the abbreviations before abstraction. The inputs $a,b$ are the operator and argument codes of an application. If
the operator code is nonzero, the root contributes no query reduct. Otherwise, a table entry is decoded as a proposed
address and answer. Equality testing compares the argument code with the fixed numeral code of that address. A match
prepends the numeral code of the answer to the tail list; a failure keeps the tail list. Thus order and repeated entries
are preserved.

Put
$$\LambdaQueryReductListCode{t}{M}:=
\LambdaListCode{\ListMap{\LambdaSyntaxCode{\cdot}}{\LambdaQuerySuccessors{t}{M}}}.$$
Keep the variable handler $V$ and left-context map $E$ from §{sec:lambda-one-step-programs}. For applications and
abstractions define
$$\begin{aligned}
J(t,a,b,l,r)&:=\LambdaListAppend\\
 &\quad\bigl(\LambdaListAppend\,(\LambdaRootQueryProgram\,t\,a\,b)
       (\LambdaListMap\,(Eb)\,l)\bigr)\\
 &\quad\bigl(\LambdaListMap\,(\LambdaTaggedCode{1}\,a)\,r\bigr),\\
A_0&:=\lambdaab{t}{\lambdaab{a}{\lambdaab{b}{\lambdaab{l}{\lambdaab{r}{
 \LambdaNumericPair\,(\LambdaTaggedCode{1}\,a\,b)\,J(t,a,b,l,r)}}}}},\\
L_0&:=\lambdaab{i}{\lambdaab{a}{\lambdaab{l}{
 \LambdaNumericPair\,(\LambdaTaggedCode{2}\,i\,a)
 (\LambdaZeroTest\,i\,\ChurchNumeral{0}
 (\LambdaListMap\,(\LambdaTaggedCode{2}\,i)\,l))}}}.
\end{aligned}$$
The state keeps the original syntax code together with the query-reduct list code. The application handler concatenates
the root, left and right lists in that order. The abstraction handler returns an empty query list when its binder is
$x_0$; otherwise it restores the binder around every body query reduct.

Extract the state fields and assemble the programs:
$$\begin{aligned}
A&:=\lambdaab{t}{\lambdaab{s}{\lambdaab{u}{
 A_0t(\LambdaNumericProjection{1}\,s)(\LambdaNumericProjection{1}\,u)
 (\LambdaNumericProjection{2}\,s)(\LambdaNumericProjection{2}\,u)}}},\\
L&:=\lambdaab{i}{\lambdaab{s}{
 L_0i(\LambdaNumericProjection{1}\,s)(\LambdaNumericProjection{2}\,s)}},\\
\LambdaQueryReductProgram&:=\lambdaab{t}{\lambdaab{e}{
 \LambdaNumericProjection{2}(\LambdaSyntaxRecursor\,V\,(At)\,L\,e)}},\\
\LambdaInputReductProgram&:=\lambdaab{t}{\lambdaab{e}{
 \LambdaListAppend\,(\LambdaReductProgram\,e)(\LambdaQueryReductProgram\,t\,e)}},\\
\LambdaInputStepTest&:=\lambdaab{t}{\lambdaab{e}{\lambdaab{d}{
 \LambdaListMember\,d\,(\LambdaInputReductProgram\,t\,e)}}}.
\end{aligned}$$
All abbreviations are expanded within the indicated abstractions. Every displayed program is closed. The full reduct
list concatenates the beta list with the query list, and the last program tests membership of the target code.

\begin{theorem*}[\termdefineas{lambda finite-table step programs}{Finite-table step programs}]
For every finite answer table $t$ and named terms $M,N$,
$$\begin{aligned}
\LambdaQueryReductProgram\,\ChurchNumeral{\LambdaAnswerTableCode{t}}\,
 \ChurchNumeral{\LambdaSyntaxCode{M}}
 &\to_\beta^*\ChurchNumeral{\LambdaQueryReductListCode{t}{M}},\\
\LambdaInputReductProgram\,\ChurchNumeral{\LambdaAnswerTableCode{t}}\,
 \ChurchNumeral{\LambdaSyntaxCode{M}}
 &\to_\beta^*\ChurchNumeral{\LambdaListCode{\ListMap{\LambdaSyntaxCode{\cdot}}{\LambdaInputSuccessors{t}{M}}}}.
\end{aligned}$$
The term $\LambdaInputStepTest$ on the table, source and target codes reduces to $\ChurchNumeral{1}$ exactly when
$N\in\LambdaInputSuccessors{t}{M}$, and reduces to $\ChurchNumeral{0}$ otherwise. These computations extend to arbitrary
numerical codes by decoding. No consistency assumption on the finite table is required.
\end{theorem*}

\begin{proof}[Proof]
For the root list, induct on the table. The empty table gives the empty-list code. At a table entry, numerical
projections recover the proposed address and answer. The numeral-code program and injectivity of syntax coding make
numerical equality exactly the required syntactic equality. Depending on this test, the list handler either retains the
tail or prepends the answer's numeral code. Zero testing of the operator code restricts this scan to the input variable.
This proves the root-list formula with its original order and duplicates.

Now use structural recursion with state
$$\ChurchNumeral{\NatPair{\LambdaSyntaxCode{M}}{\LambdaQueryReductListCode{t}{M}}}.$$
The variable case uses the unchanged variable handler. In the application case, projections recover both child codes and
both query lists. The root calculation and the two context maps give exactly the defining three lists. The abstraction
case splits at binder index zero: zero discards the body query list, and a positive index restores the binder around
each body query reduct. Thus the fold gives the required state, and its second projection gives the query list.
Concatenation with the beta list gives the full list. Membership testing is exact because syntax coding is injective.
Finally, every table and term code decodes, so the inverse coding identities give the arbitrary-code statements.
Uniqueness of numeral outputs excludes an incorrect Boolean answer.
\end{proof}

The certificate fold can now use this one-step tester. Define
$$\begin{aligned}
F(t,a,b,r,e,d)&:=\LambdaZeroTest\,(\LambdaAlphaTest\,e\,a)\,\ChurchNumeral{0}\\
 &\quad\bigl(\LambdaZeroTest\,(\LambdaInputStepTest\,t\,a\,b)\,\ChurchNumeral{0}\,(rbd)\bigr),\\
H_c&:=\lambdaab{t}{\lambdaab{c}{\lambdaab{r}{\lambdaab{e}{\lambdaab{d}{
 F(t,\LambdaNumericProjection{1}\,c,\LambdaNumericProjection{2}\,c,r,e,d)}}}}},\\
\LambdaInputCertificateCheck&:=\lambdaab{t}{\lambdaab{c}{
 \LambdaListRecursor\,(H_ct)\,\LambdaAlphaTest\,c}}.
\end{aligned}$$
Expand $F$ in the handler. The list-fold value remains a function of the current source and fixed target, so both
endpoints are supplied after the table and certificate. The empty certificate compares its endpoints up to
alpha-equivalence. At a nonempty certificate, a failed join or failed one-step check returns zero; otherwise the tail
function receives the new source. All these terms are closed.

\begin{theorem*}[\termdefineas{lambda finite-table certificate checker}{Finite-table certificate checking by a
lambda term}]
For every table $t$, certificate $c$ and named endpoints $M,N$,
$$\begin{aligned}
&\LambdaInputCertificateCheck\,\ChurchNumeral{\LambdaAnswerTableCode{t}}\,
 \ChurchNumeral{\LambdaCertificateCode{c}}\,
 \ChurchNumeral{\LambdaSyntaxCode{M}}\,\ChurchNumeral{\LambdaSyntaxCode{N}}\\
&\qquad\to_\beta^*
\begin{cases}
\ChurchNumeral{1},&\LambdaInputCertificate{t}{M}{N}{c}=\mathrm{true},\\
\ChurchNumeral{0},&\LambdaInputCertificate{t}{M}{N}{c}=\mathrm{false}.
\end{cases}
\end{aligned}$$
The same holds for arbitrary numerical inputs after decoding. In particular, reduction to one is equivalent to
acceptance by the finite certificate check.
\end{theorem*}

\begin{proof}[Proof]
For a fixed table $t$, define closed values recursively by
$$\begin{aligned}
W_{t,[]}&:=\LambdaAlphaTest,\\
W_{t,\Pair{A}{B}::c}&:=H_c\ChurchNumeral{\LambdaAnswerTableCode{t}}\,
 \ChurchNumeral{\NatPair{\LambdaSyntaxCode{A}}{\LambdaSyntaxCode{B}}}\,W_{t,c}.
\end{aligned}$$
List recursion reduces the checker on the table and certificate codes to this value. Induct on the certificate, keeping
both endpoints arbitrary. For the empty certificate, alpha-equivalence decision is precisely the required check. In the
nonempty case, projections extract the listed source and target. The alpha test checks the source join, the finite-table
step program checks the listed step, and the induction hypothesis checks the tail at the new source. These are exactly
the three conditions defining the certificate check. Coding and decoding extend the conclusion to arbitrary inputs. If a
rejected certificate also reduced to one, it would have the two distinct numeral outputs zero and one, contradicting
confluence and numeral injectivity.
\end{proof}

\begin{corollary*}[\termdefineas{lambda checked input-query certificates}{Input-query reductions certified by a
closed checker}]
For any name $p$ and named terms $M,N$, the relation $\LambdaInputSteps{p}{[M]}{[N]}$ holds if and only if there are a
finite table agreeing with $p$ and a finite certificate for which the closed checker, supplied with their codes and the
codes of $M,N$, reduces to $\ChurchNumeral{1}$.
\end{corollary*}

\begin{proof}[Proof]
Apply the finite-certificate equivalence of §{sec:lambda-input-certificates} and the exact acceptance assertion just
proved. The coding inverses turn the finite witnesses into numerical inputs and recover them in the reverse direction.
\end{proof}

### Substitution and composition {#sec:lambda-input-composition}

\begin{mathmeta}
  \vars{i,k}{Nat}
\end{mathmeta}

\begin{lemma*}[\termuseas{uniform oracle substitution lemma}{Lambda substitution and composition}]
Computable partial maps on names are closed under composition whenever the intermediate names lie in the domain of the
second map. If closed terms $Q$ and $P$ compute the inner and outer maps, respectively, their composite is computed by
the closed term
$$C_{P,Q}:=\lambdaab{a}{\lambdaab{b}{P\,(Q\,a)\,b}}.$$
Here $a,b$ are distinct variables different from $o$. The identity is computed by $\lambdaab{a}{a}$.
\end{lemma*}

\begin{proof}[Proof]
Fix a valid input name $p$ and let $q$ be its image under the inner map. Put $R=Q\,o$. For every $i$, the term
$R\ChurchNumeral{i}$ reduces with input $p$ to $\ChurchNumeral{q(i)}$. In a finite reduction of the outer program with
input $q$, replace the free variable $o$ by $R$. A beta step remains a beta step by capture-avoiding substitution. A
query at $i$ is replaced by the finite reduction just described; closed numerals are unaffected by substitution.
Application contexts lift these finite reductions. Under an abstraction, choose a binder fresh for both bodies, the
replacement, and $o$, then lift the reduction through that binder.

To justify fresh renaming within this induction, strengthen the claim to finite substitution lists: require that the
substituted image of $o$, applied to each numeral, produces the corresponding digit of $q$. Prepending a renaming of a
binder different from $o$ preserves that image. The induction therefore applies to the renamed bodies. Concatenating the
resulting finite reductions proves the substitution assertion for the whole computation.

Two beta steps reduce $C_{P,Q}\,o\,\ChurchNumeral{n}$ to $P\,(Q\,o)\,\ChurchNumeral{n}$. Since $P$ is closed, this is
exactly the result of substituting $R$ for $o$ in $P\,o\,\ChurchNumeral{n}$. The preceding argument supplies the
required output, and confluence excludes other numeral outputs. Closedness of $P,Q$ also gives closedness of $C_{P,Q}$.
The identity computation was verified above.
\end{proof}

\begin{proposition*}[\termdefineas{Substitution of a computable input name}{Substitution of a computable input name}]
Let $A,P$ be closed terms, and suppose $A$ computes every digit of a name $p$ by ordinary beta reduction.
If $P$ returns $m$ with input name $p$ and numerical input $n$, then
$$PA\ChurchNumeral{n}\to_\beta^*\ChurchNumeral{m}.$$
In particular, if $P$ computes a map $F$ on a domain containing $p$, the closed term $PA$ computes the
ordinary numerical function $n\mapsto F(p)(n)$.
\end{proposition*}

\begin{proof}[Proof]
Use the preceding substitution argument with replacement $A$. Every input query is replaced by the given finite
beta reduction computing that digit. Beta steps remain beta steps under substitution, and the same fresh-binder
argument handles abstractions. Equivalently, apply the beta/query substitution result with any auxiliary input
name: after substitution the initial term is closed, so no query step is possible. A query requires a free
occurrence of $o$, whereas beta reduction preserves closedness. Induction through the finite reduction therefore
leaves only ordinary beta steps. Closedness of $PA$ and uniqueness of numerical outputs give the last assertion.
\end{proof}

For a uniform family of constant input names $p_i(n)=i$, put
$$K_i:=\lambdaab{u}{\ChurchNumeral{i}},\qquad H:=\lambdaab{a}{P\,(\lambdaab{u}{a})}.$$
One beta step gives $\BetaConvertible{H\ChurchNumeral{i}}{PK_i}$. Thus whenever $P$ terminates on every constant name,
$H\ChurchNumeral{i}\ChurchNumeral{k}$ returns the program's $k$th output on $p_i$ by ordinary beta reduction.
The single closed term
$$\lambdaab{z}{H\,(\LambdaNumericProjection{1}z)\,(\LambdaNumericProjection{2}z)}$$
computes these outputs jointly from $\NatPair{i}{k}$. No decision procedure for the program's domain of names is
needed: validity of the constant names alone supplies termination.

### Computable points and maps on Baire space {#sec:lambda-baire-space}

\begin{mathmeta}
  \vars{p}{Name}
\end{mathmeta}

A point $p\in\BaireSpace$ is \termdefineas{computable point}{computable} if some index $e$ computes its digits, so
$\varphi_e(n)=p(n)$ for every $n$. A partial map $\PartialFunctionMap{F}{\BaireSpace}{\BaireSpace}$ is a
\termdefine{computable map on Baire space} if it has a Type-Two lambda realizer in the preceding definition. Thus the
same closed term computes every output coordinate at every point of the specified domain. It may also produce outputs
outside that domain.

Every such map is continuous on its domain with the subspace topology. Indeed, fix a valid name and one coordinate.
Finite use gives a cylinder on which the required numeral is still returned; intersect this cylinder with the domain.
Output uniqueness makes the coordinate function constant there. All coordinates are therefore continuous into discrete
$\NN$, which is equivalent to continuity into Baire space. Neither openness nor decidability of the domain is required.

The converse is false as stated: not every continuous map is computable. Even when finite-prefix bounds are effectively
available, the output values themselves may contain non-computable information; for example, the constant map with value
a non-computable point of Baire space is continuous with trivial modulus but is not computable. Computability is
continuity together with an effective procedure which, from the requested coordinate and the finite input information
used, produces the corresponding output value.

### Predicates relative to one parameter {#sec:lambda-relative-predicates}

\begin{mathmeta}
  \vars{i,n}{Nat}
  \vars{\varepsilon}{Name}
\end{mathmeta}

Fix $\varepsilon:\NN\to\NN$ and an injective numerical coding $c:S\to\NN$. A closed term $P$ decides a predicate
$R$ on $S$ relative to $\varepsilon$ when, for every $s\in S$, it returns one on code $c(s)$ if $R(s)$ holds and
zero otherwise, using the beta/query rule with input $\varepsilon$. Both alternatives must terminate. This definition
requires no decision procedure for the range of $c$ and says nothing about other numerical inputs.

\begin{lemma*}[\termdefineas{Relative Boolean decision programs}{Relative Boolean decision programs}]
Predicates decidable relative to one fixed parameter are closed under complement and finite intersection.
\end{lemma*}

\begin{proof}[Proof]
Let $P,Q$ decide the two predicates. For complement, compute the output of $P$ and apply the closed numerical term
that returns one on zero and zero on a positive input. For intersection, compute both outputs and multiply them.
The multiplication term returns one exactly when both answers are one. Beta/query reductions lift through the
application contexts, and both component computations terminate on every valid input code. These
compositions are closed because their component terms are closed and their input variables are bound.
Iterating intersection handles any nonempty finite family; the constant-one program handles the empty family.
\end{proof}

For a sequence of predicates $R_i$ on $S$, define a parameter $\varepsilon$ by
$$
\varepsilon(\NatPair{i}{n})=
\begin{cases}
1,&\exists s\in S\ (c(s)=n\ \land\ R_i(s)),\\
0,&\text{otherwise}.
\end{cases}
$$
The fixed row $i$ is read by the closed term
$$P_i:=\lambdaab{o}{\lambdaab{z}{o\bigl(\LambdaNumericPair\,\ChurchNumeral{i}\,z\bigr)}}.$$
Two beta steps, the numerical pairing reduction, and one input query return
$\ChurchNumeral{\varepsilon(\NatPair{i}{c(s)})}$ on input code $c(s)$. Injectivity of $c$ makes this numeral one
exactly when $R_i(s)$ holds, and zero otherwise. This proves the common-parameter proposition of
§{sec:edst-relative-programs} with an explicit program for each row. The parameter may be noncomputable.

For completeness, the countability assertion in §{sec:edst-relative-programs} uses the syntax coding already
constructed here. Every closed alpha-class has a named representative and hence a natural-number program index.
Choose such an index for each relatively computable function or predicate. If two chosen indices coincide,
output uniqueness applied with the same parameter and input code equates their numerical outputs. Injectivity
of the output coding equates function values; for predicates, opposite truth values would give the distinct
outputs zero and one. Thus each assignment of indices is injective.

### Pairing and projection {#sec:tte-name-pairs}

\begin{mathmeta}
  \forward{NatPair,LambdaNumericPair,LambdaNumericProjection}
  \define{NamePair,NameProjection,LambdaPairOutputs,LambdaProjectOutput}
  \vars{n}{Nat}
  \vars{p,q}{Name}
  \vars{i}{Nat}
\end{mathmeta}

Pair names pointwise:
$$\NamePair{p}{q}(n):=\NatPair{p(n)}{q(n)}.$$
Write $\NameProjection{1}{r}$ and $\NameProjection{2}{r}$ for the names obtained by applying the first and second
numerical inverse projections at every coordinate of $r$. The numerical inverse identities give
$$\NameProjection{1}{\NamePair{p}{q}}=p,\qquad
\NameProjection{2}{\NamePair{p}{q}}=q,\qquad
\NamePair{\NameProjection{1}{r}}{\NameProjection{2}{r}}=r.$$
Thus this codes every pair of names by exactly one name.

Choose closed lambda terms $\LambdaNumericPair$ and $\LambdaNumericProjection{i}$ implementing these numerical functions
on Church numerals. Their concrete constructions and reductions are given in §{sec:lambda-numerical-pairing} and
§{sec:lambda-numerical-projections}; only their stated numerical behavior is used here. Given closed programs $P,Q$,
define
$$\begin{aligned}
\LambdaPairOutputs{P}{Q}&:=\lambdaab{a}{\lambdaab{b}{\LambdaNumericPair\,(Pab)\,(Qab)}},\\
\LambdaProjectOutput{i}{P}&:=\lambdaab{a}{\lambdaab{b}{\LambdaNumericProjection{i}\,(Pab)}}\qquad(i=1,2).
\end{aligned}$$
Both constructions yield closed finite lambda terms. The arguments $a,b$ pass the same input name and output coordinate
to the component programs.

\begin{lemma*}[\termdefineas{lambda pairing and projection of names}{Pairing and projection of names}]
Let $P,Q$ be Type-Two lambda realizers of $F,G:D\to\BaireSpace$. Then $\LambdaPairOutputs{P}{Q}$ realizes
$p\mapsto\NamePair{F(p)}{G(p)}$, and $\LambdaProjectOutput{i}{P}$ realizes $p\mapsto\NameProjection{i}{F(p)}$ for
$i=1,2$, all on the same domain $D$.
\end{lemma*}

\begin{proof}[Proof]
Fix $p\in D$ and $n\in\NN$. Two beta steps unfold the pairing program to
$$\LambdaNumericPair\,(P\,o\,\ChurchNumeral{n})\,(Q\,o\,\ChurchNumeral{n}).$$
Reduce the two component applications to $\ChurchNumeral{F(p)(n)}$ and $\ChurchNumeral{G(p)(n)}$. The numerical pairing
reduction then returns $\ChurchNumeral{\NatPair{F(p)(n)}{G(p)(n)}}$. Similarly, two beta steps unfold the projection
program to
$$\LambdaNumericProjection{i}\,(P\,o\,\ChurchNumeral{n}).$$
Reduce the component application and apply the numerical projection reduction. This returns the required coordinate of
$\NameProjection{i}{F(p)}$. Closedness of the component programs prevents capture in the outer substitutions. All
reductions are finite, and confluence excludes other numeral outputs. The argument uses no behavior outside $D$.
\end{proof}

### Tags and branching {#sec:tte-name-tags}

\begin{mathmeta}
  \forward{LambdaSucc,LambdaPred,LambdaZeroTest}
  \define{NameTail,LambdaNameTail,LambdaNamePrefix,LambdaTagBranch,LambdaCoproductCase}
  \vars{m,n,t}{Nat}
  \vars{p}{Name}
\end{mathmeta}

Write $\NameTail{p}(n):=p(n+1)$ for the tail of a name. Use the usual closed Church-numeral terms: successor
$\LambdaSucc$ sends $n$ to $n+1$, predecessor $\LambdaPred$ sends zero to zero and $n+1$ to $n$, and $\LambdaZeroTest$
chooses the first of its two branches at zero and the second at a positive numeral. The calculations in
§{sec:lambda-numeral-operations} verify these familiar operations. Define
$$\begin{aligned}
\LambdaNameTail&:=\lambdaab{a}{\lambdaab{b}{a(\LambdaSucc\,b)}},\\
\LambdaNamePrefix{t}&:=\lambdaab{a}{\lambdaab{b}{
\LambdaZeroTest\,b\,\ChurchNumeral{t}\,\bigl(a(\LambdaPred\,b)\bigr)}}\qquad(t\in\NN).
\end{aligned}$$
The first term removes the initial digit; the second prefixes the fixed tag $t$.

\begin{lemma*}[\termdefineas{lambda prefix and tail}{Prefixing and removing a tag}]
For every name $p$ and $t,n\in\NN$,
$$\begin{aligned}
&\LambdaInputSteps{p}{\LambdaNameTail\,o\,\ChurchNumeral{n}}{\ChurchNumeral{p(n+1)}},\\
&\LambdaInputSteps{p}{\LambdaNamePrefix{t}\,o\,\ChurchNumeral{0}}{\ChurchNumeral{t}},\\
&\LambdaInputSteps{p}{\LambdaNamePrefix{t}\,o\,\ChurchNumeral{n+1}}{\ChurchNumeral{p(n)}}.
\end{aligned}$$
Thus these terms realize $p\mapsto\NameTail{p}$ and $p\mapsto t\concat p$ on all names, respectively.
\end{lemma*}

\begin{proof}[Proof]
For the tail term, two beta steps expose $o(\LambdaSucc\,\ChurchNumeral{n})$. Successor reduces the query argument to
$\ChurchNumeral{n+1}$, and one query returns $\ChurchNumeral{p(n+1)}$. For prefixing, two beta steps expose the zero
test of the output coordinate. At coordinate zero it selects $\ChurchNumeral{t}$ without evaluating the query branch. At
coordinate $n+1$ it selects $o(\LambdaPred\,\ChurchNumeral{n+1})$; predecessor returns $\ChurchNumeral{n}$, and one
query gives $\ChurchNumeral{p(n)}$. These calculations cover coordinate zero and every successor coordinate. Both terms
are closed, and confluence excludes other numeral outputs.
\end{proof}

For closed programs $P,Q$, define a tag selector by
$$\LambdaTagBranch{P}{Q}:=\lambdaab{a}{\lambdaab{b}{
\LambdaZeroTest\,(a\ChurchNumeral{0})\,(Pab)\,(Qab)}}.$$
Use the composition term $C_{P,Q}$ from §{sec:lambda-input-composition} to form
$$\LambdaCoproductCase{P}{Q}:=
\LambdaTagBranch{C_{P,\LambdaNameTail}}{C_{Q,\LambdaNameTail}}.$$
All component programs are inserted as closed lambda terms. Both constructions are therefore closed and finite.

\begin{lemma*}[\termdefineas{tag-directed computation lemma}{Tag-directed computation}]
Let $P,Q$ be closed programs and let $p$ be a name. If $p(0)=0$ and $P$ returns $m$ on name $\NameTail{p}$ at coordinate
$n$, then $\LambdaCoproductCase{P}{Q}$ returns $m$ on name $p$ at coordinate $n$. If $p(0)=1$, the analogous assertion
holds with $Q$. No termination assumption is made about the unused program on that tail.
\end{lemma*}

\begin{proof}[Proof]
First apply the tag selector to $o,\ChurchNumeral{n}$. Two beta steps expose the two branch applications and the test
$o\ChurchNumeral{0}$. One query returns the tag. If the tag is zero, the zero-test and true-selection reductions return
$P\,o\,\ChurchNumeral{n}$; if it is one, false selection returns $Q\,o\,\ChurchNumeral{n}$. These finite reductions do
not reduce the discarded branch. Closedness of the branch programs ensures that the binder substitutions do not capture
the input variable.

Now use $C_{P,\LambdaNameTail}$ and $C_{Q,\LambdaNameTail}$ as the two branch programs. The tail lemma supplies every
digit of $\NameTail{p}$. The input-substitution proof of composition therefore transforms a finite reduction of the
selected original program on that tail into a finite reduction with input name $p$. Concatenate this with the selector
reduction. Only the selected program needs a successful computation. Confluence makes the resulting numeral output
unique.
\end{proof}

## Recursion, Search, and Uniform Program Indices {#sec:lambda-input-programs}

### Primitive recursion with an input name {#sec:lambda-input-recursion}

\begin{mathmeta}
  \vars{k,n,r}{Nat}
\end{mathmeta}

The recursor from §{sec:lambda-primitive-recursion} also permits queries to an input name during the update. Use the
input variable $o$ and finite reductions $\LambdaInputSteps{p}{M}{N}$ just defined. Besides beta steps, these reductions
allow $o\ChurchNumeral{i}$ to return $\ChurchNumeral{p(i)}$. Choose the recursor's internal binders distinct from $o$,
so that they do not capture the input variable. The program is still an ordinary finite lambda term; only the behavior
of the supplied argument is specified by the query rule.

\begin{theorem*}[\termdefineas{lambda recursion with an input name}{Primitive recursion with an input name}]
Let $D\IncludedIn\BaireSpace$, and let $B,H$ be closed lambda terms. Suppose that for every $p\in D$ there are a natural
number $a(p)$ and a function $g(p,\cdot,\cdot):\NN^2\to\NN$ such that, for all $k,r\in\NN$,
$$\begin{aligned}
&\LambdaInputSteps{p}{B\,o}{\ChurchNumeral{a(p)}},\\
&\LambdaInputSteps{p}{H\,o\,\ChurchNumeral{k}\,\ChurchNumeral{r}}{\ChurchNumeral{g(p,k,r)}}.
\end{aligned}$$
Define
$$r_p(0):=a(p),\qquad r_p(k+1):=g(p,k,r_p(k)).$$
Then the single closed term $\LambdaParamRec{B}{H}$ satisfies
$$\LambdaInputSteps{p}{\LambdaParamRec{B}{H}\,o\,\ChurchNumeral{n}}{\ChurchNumeral{r_p(n)}}$$
for every $p\in D$ and $n\in\NN$. It is a \termuse{Type-Two lambda realizer} of the name map
$p\mapsto\Sequence{r_p(n)}{n\in\NN}$ on $D$.
\end{theorem*}

\begin{proof}[Proof]
Fix $p\in D$ and put $G:=Ho$. Since $H$ is closed, the only possible free variable of $G$ is $o$. Unfold the
parameterized recursor and reduce $Bo$ to $\ChurchNumeral{a(p)}$. The three outer beta steps of the recursor then expose
its iteration body. The freshness of the internal binders preserves $G$ throughout these substitutions; it need not be
closed.

Write
$$S_k:=\LambdaPairValue{\ChurchNumeral{k}}{\ChurchNumeral{r_p(k)}}.$$
Each state is closed. One application of $\LambdaRecUpdate{G}$ first selects its index and value. Successor produces the
next index; the assumed reduction of $G$ on the old index and value produces the next value, using whatever queries that
reduction requires. Pair formation therefore gives
$$\LambdaInputSteps{p}{\LambdaRecUpdate{G}\,S_k}{S_{k+1}}.$$
Induction on the iteration count now yields
$$\LambdaInputSteps{p}{\LambdaIter{\LambdaRecUpdate{G}}{S_0}{n}}{S_n}.$$
The zero case is the empty reduction. At a successor stage, reduce the preceding iterate and then perform the single
update just described.

The Church numeral unfolds to precisely this iteration: its binders also avoid $o$, so the iteration formula applies
even though $\LambdaRecUpdate{G}$ may have that free variable. Selecting the value component of the final state returns
$\ChurchNumeral{r_p(n)}$. All stages use finite reductions, hence so does their concatenation. Closedness of $B,H$ makes
$\LambdaParamRec{B}{H}$ closed independently of $p$ and $n$. By confluence for beta/query reduction, no different
numeral can be returned. This proves the exact-output condition for a realizer. No test for membership in $D$ is needed.
\end{proof}

\begin{corollary*}[\termdefineas{finite-stage lambda recursion}{Finite-stage recursion}]
Let $B,H$ be closed, fix an input name $p$ and a natural number $n$, and let $v_0,\ldots,v_n$ be natural numbers.
Suppose that
$$\LambdaInputSteps{p}{B\,o}{\ChurchNumeral{v_0}}$$
and that, for each $k<n$,
$$\LambdaInputSteps{p}{H\,o\,\ChurchNumeral{k}\,\ChurchNumeral{v_k}}{\ChurchNumeral{v_{k+1}}}.$$
Then
$$\LambdaInputSteps{p}{\LambdaParamRec{B}{H}\,o\,\ChurchNumeral{n}}{\ChurchNumeral{v_n}}.$$
No termination assumption is needed at later stages or at other state values.
\end{corollary*}

\begin{proof}[Proof]
Use the states $\LambdaPairValue{\ChurchNumeral{k}}{\ChurchNumeral{v_k}}$ in the preceding argument and stop the
induction at $n$. Each successor step uses only the assumed update for that stage. The base computation and final
selection are unchanged. This also covers $n=0$, when no update is performed.
\end{proof}

\begin{example*}[Iteration of an input name]
Take
$$B:=\lambdaab{a}{\ChurchNumeral{0}},\qquad H:=\lambdaab{a}{\lambdaab{k}{\lambdaab{r}{ar}}}.$$
Then $\LambdaParamRec{B}{H}$ realizes, for every input name $p$, the sequence
$$r_p(0)=0,\qquad r_p(k+1)=p(r_p(k)).$$
Thus the successive values are $0,p(0),p(p(0)),\ldots$; each answer determines the next query address.
\end{example*}

\begin{proof}[Proof]
The base term returns $\ChurchNumeral{0}$ by one beta step. For the update, three beta steps reduce
$H\,o\,\ChurchNumeral{k}\,\ChurchNumeral{r}$ to $o\ChurchNumeral{r}$, and one query returns $\ChurchNumeral{p(r)}$. Both
terms are closed. Apply the theorem with $a(p)=0$ and $g(p,k,r)=p(r)$.
\end{proof}

### Reading a finite input prefix {#sec:lambda-input-prefixes}

\begin{mathmeta}
  \define{LambdaPrefixStep,LambdaInputPrefix}
  \vars{m,n,u}{Nat}
  \vars{k}{Nat}
  \vars{p,q}{Name}
  \vars{s_*}{Seq(Nat)}
\end{mathmeta}

To read the first $n$ values of an input name, store the values already read as a numerical list code and append one new
value at each stage. For a term $A$, put
$$\begin{aligned}
\LambdaPrefixStep{A}&:=\lambdaab{k}{\lambdaab{u}{
 \LambdaListAppend\,u\,(\LambdaListCons\,(Ak)\,\ChurchNumeral{0})}},\\
\LambdaInputPrefix&:=\lambdaab{a}{\LambdaRecursor\,\LambdaPrefixStep{a}\,\ChurchNumeral{0}}.
\end{aligned}$$
Expand the abbreviation $\LambdaPrefixStep{a}$ before abstracting over $a$. Choose its binders $k,u$ fresh for $A$ and
distinct from the input variable $o$. The term $\LambdaInputPrefix$ is closed. Appending a singleton, rather than
prepending it, preserves the order of the input values.

\begin{proposition*}[\termdefineas{lambda finite input prefix}{Reading a finite input prefix}]
Fix names $p,q$ and $n\in\NN$. Let $A$ have no free variable other than possibly $o$. If
$$\LambdaInputSteps{p}{A\,\ChurchNumeral{k}}{\ChurchNumeral{q(k)}}\qquad(k<n),$$
then
$$\LambdaInputSteps{p}{\LambdaInputPrefix\,A\,\ChurchNumeral{n}}
 {\ChurchNumeral{\LambdaListCode{\restrict{q}{n}}}}.$$
In particular, taking $A=o$ gives the exact numerical-output identity
$$\LambdaInputSteps{p}{\LambdaInputPrefix\,o\,\ChurchNumeral{n}}{\ChurchNumeral{m}}
 \quad\Longleftrightarrow\quad m=\LambdaListCode{\restrict{p}{n}}.$$
The first assertion requires no computation of $A\,\ChurchNumeral{k}$ for $k\ge n$.
\end{proposition*}

\begin{proof}[Proof]
One beta step exposes the recursor with update $\LambdaPrefixStep{A}$ and initial value $\ChurchNumeral{0}$. Write
$s_k:=\restrict{q}{k}$. At stage $k$, the state supplied for $u$ is
$\ChurchNumeral{\LambdaListCode{s_k}}$. The empty prefix has list code zero.
At stage $k<n$, two beta steps expose the update body; the
assumed computation of $A\ChurchNumeral{k}$ and the list constructor produce the code of $[q(k)]$. The append program
then produces the code of $s_k\concat[q(k)]=s_{k+1}$. All state values are closed numerals, while the update has no free
variable other than possibly $o$. The finite-stage recursion argument in §{sec:lambda-input-recursion} therefore yields
the code of $s_n$. For $n=0$ there is no update and no input query is needed.

For $A=o$ and $q=p$, each required computation is one input-query step. This proves existence of the stated output;
confluence and normality of numerals exclude every different numerical output. More generally, agreement of two names
below $n$ gives the same prefix code, with no condition on their later values. Conversely, equal output codes imply
equal prefixes because list encoding is injective.
\end{proof}

### Checking input answers and bounded certificates {#sec:lambda-input-check-programs}

\begin{mathmeta}
  \define{LambdaAnswerAgreementCheck,LambdaInputCandidateCheck,LambdaBoundedInputCheck}
  \vars{s}{Nat}
\end{mathmeta}

The checker in §{sec:lambda-input-certificate-programs} treats an answer table as finite numerical data. We now compare
those data with the actual input name and implement the bounded test from §{sec:lambda-input-certificates}. The list
recursor of §{sec:lambda-finite-lists} also works when its handler queries the input.

\begin{lemma*}[\termdefineas{lambda list recursion with input}{List recursion with an input name}]
Fix an input name $p$. Let $Z,H$ have no free variables other than possibly $o$, and choose the internal binders of the
list fold distinct from $o$. Suppose that terms $V_l$, indexed by finite numerical lists, satisfy
$$\LambdaInputSteps{p}{Z}{V_{[]}},\qquad
\LambdaInputSteps{p}{H\,\ChurchNumeral{a}\,V_l}{V_{a::l}}.$$
Then
$$\LambdaInputSteps{p}{\LambdaListRecursor\,H\,Z\,\ChurchNumeral{\LambdaListCode{l}}}{V_l}.$$
\end{lemma*}

\begin{proof}[Proof]
The two beta steps unfolding the fold and the two steps supplying its parameters remain valid: the internal binders
cannot capture the free input variable. The empty-list branch returns $Z$. The nonempty branch extracts the head and
tail code, giving $H\ChurchNumeral{a}$ applied to the fold on the tail. Induct on the list, lift the tail reduction
through application, and then use the assumed reduction for $H$. These operations use precisely the permitted beta/query
contexts; no closedness assumption on the intermediate $V_l$ is needed.
\end{proof}

Define the following closed terms, expanding the displayed bodies before abstraction and keeping all internal binders
fresh:
$$\begin{aligned}
H_a&:=\lambdaab{o}{\lambdaab{c}{\lambdaab{r}{
 \LambdaZeroTest\,
  \bigl(\LambdaEqual\,(o(\LambdaNumericProjection{1}\,c))
                         (\LambdaNumericProjection{2}\,c)\bigr)
  \,\ChurchNumeral{0}\,r}}},\\
\LambdaAnswerAgreementCheck&:=\lambdaab{o}{\lambdaab{t}{
 \LambdaListRecursor\,(H_ao)\,\ChurchNumeral{1}\,t}}.
\end{aligned}$$
An entry code $c$ supplies a query address and a proposed answer. The handler compares the actual answer with the
proposed one, returning zero on a mismatch and otherwise retaining the tail result. The empty table returns one.
Repeated addresses require no special treatment: every listed answer must agree with the same input name.

\begin{proposition*}[\termdefineas{lambda answer table agreement program}{Comparing a table with the input}]
For every name $p$ and finite answer table $t$,
$$\begin{aligned}
&\LambdaAnswerAgreementCheck\,o\,\ChurchNumeral{\LambdaAnswerTableCode{t}}
\\
&\qquad\LambdaInputSteps{p}{}{\begin{cases}
\ChurchNumeral{1},&\forall\Pair{i}{v}\in t\;p(i)=v,\\
\ChurchNumeral{0},&\exists\Pair{i}{v}\in t\;p(i)\ne v.
\end{cases}}
\end{aligned}$$
This holds for every numerical table code after decoding. Reduction to one is equivalent to agreement of the decoded
table with $p$.
\end{proposition*}

\begin{proof}[Proof]
At a nonempty entry, the projections return its address and proposed answer. One input-query step returns the actual
answer, and equality testing decides whether the two numbers coincide. Apply the list-recursion lemma with $V_l$ equal
to one or zero according as every decoded pair in $l$ agrees with $p$ or not. The empty case is one, and the handler has
exactly the required conjunction behavior. The numerical coding inverses give the arbitrary-code assertion. Confluence
with input queries excludes reduction to one when the computed answer is zero.
\end{proof}

Combine this comparison with the closed certificate checker. Using numerical codes throughout, put
$$\begin{aligned}
D(o,e,d,t,c)&:=\LambdaZeroTest\,(\LambdaAnswerAgreementCheck\,o\,t)
 \,\ChurchNumeral{0}\\
 &\quad(\LambdaInputCertificateCheck\,t\,c\,e\,d),\\
\LambdaInputCandidateCheck&:=\lambdaab{o}{\lambdaab{e}{\lambdaab{d}{\lambdaab{b}{
 D(o,e,d,\LambdaNumericProjection{1}\,b,\LambdaNumericProjection{2}\,b)}}}}.
\end{aligned}$$
Expand $D$ in the last line. For a candidate code $b$, this program returns one exactly when its decoded table agrees
with $p$ and its decoded certificate passes the finite-table check for the decoded endpoints $e,d$; otherwise it returns
zero. Indeed, the projections extract the two codes, the preceding proposition checks agreement, and
§{sec:lambda-input-certificate-programs} supplies the certificate result. Zero testing forms their conjunction.

Finally use the recursor of §{sec:lambda-input-recursion} to test all candidate codes below a supplied bound:
$$\begin{aligned}
H_b&:=\lambdaab{o}{\lambdaab{e}{\lambdaab{d}{\lambdaab{k}{\lambdaab{r}{
 \LambdaZeroTest\,r\,(\LambdaInputCandidateCheck\,o\,e\,d\,k)
 \,\ChurchNumeral{1}}}}}},\\
\LambdaBoundedInputCheck&:=\lambdaab{o}{\lambdaab{e}{\lambdaab{d}{\lambdaab{s}{
 \LambdaRecursor\,(H_b\,o\,e\,d)\,\ChurchNumeral{0}\,s}}}}.
\end{aligned}$$
The initial value says that no candidate has yet succeeded. At stage $k$, keep an earlier success; if there is none, use
the answer for candidate $k$. These definitions give closed terms.

\begin{theorem*}[\termdefineas{lambda bounded input certificate program}{Bounded input-certificate checking by a
lambda term}]
For every name $p$, named terms $M,N$, and bound $s$,
$$\begin{aligned}
&\LambdaBoundedInputCheck\,o\,\ChurchNumeral{\LambdaSyntaxCode{M}}
 \,\ChurchNumeral{\LambdaSyntaxCode{N}}\,\ChurchNumeral{s}
 \\
&\qquad\LambdaInputSteps{p}{}{\begin{cases}
\ChurchNumeral{1},&\LambdaInputTest{p}{s}{M}{N}=\mathrm{true},\\
\ChurchNumeral{0},&\LambdaInputTest{p}{s}{M}{N}=\mathrm{false}.
\end{cases}}
\end{aligned}$$
The assertion also holds for arbitrary numerical endpoint codes after decoding. Reduction to one is equivalent to a
successful bounded test.
\end{theorem*}

\begin{proof}[Proof]
Induct on $s$ using primitive recursion with the input name. At zero there are no candidate codes below the bound, so
the answer is zero. Increasing the bound from $k$ to $k+1$ adds precisely candidate $k$. The handler therefore computes
the disjunction of the previous result and the new candidate result, which is the defining recurrence for the bounded
test. Each stage terminates by the candidate computation above. Confluence with input queries excludes any other numeral
output.
\end{proof}

\begin{corollary*}[\termdefineas{lambda bounded program reduction criterion}{Reduction detected by a bounded lambda
program}]
For every name $p$ and named terms $M,N$,
$$\begin{aligned}
\LambdaInputSteps{p}{[M]}{[N]}
\quad\Longleftrightarrow\quad
&\exists s\in\NN\\
&\LambdaInputSteps{p}{\LambdaBoundedInputCheck\,o\,\ChurchNumeral{\LambdaSyntaxCode{M}}
 \,\ChurchNumeral{\LambdaSyntaxCode{N}}\,\ChurchNumeral{s}}{\ChurchNumeral{1}}.
\end{aligned}$$
\end{corollary*}

\begin{proof}[Proof]
The finite-stage detection theorem in §{sec:lambda-input-certificates} characterizes the left side by success of some
bounded test. Apply the exact acceptance statement just proved. The existential bound concerns finite certificate codes;
it imposes no predetermined bound on the length of a reduction.
\end{proof}

### Unbounded search with an input name {#sec:lambda-input-search}

\begin{mathmeta}
  \define{LambdaSearchProgram}
  \vars{p}{Name}
  \vars{k,m,n,r}{Nat}
\end{mathmeta}

Use the search term of §{sec:lambda-numerical-search} with tests that may query the input name. For a closed term $H$,
define the closed wrapper
$$\LambdaSearchProgram{H}:=\lambdaab{a}{\lambdaab{b}{\LambdaSearch\,(Hab)}}.$$
Here $a$ supplies the input name and $b$ supplies the output coordinate. The test itself is the term $Hab$.

\begin{theorem*}[\termdefineas{lambda sequential search theorem}{Sequential search by a closed lambda term}]
Let $D\IncludedIn\BaireSpace$, let $H$ be closed, and let $j:D\times\NN\to\NN$. Suppose that for every $p\in D$ and
$n\in\NN$,
$$\LambdaInputSteps{p}{H\,o\,\ChurchNumeral{n}\,\ChurchNumeral{j(p,n)}}{\ChurchNumeral{0}},$$
and that for every $k<j(p,n)$ there is $r\in\NN$ such that
$$\LambdaInputSteps{p}{H\,o\,\ChurchNumeral{n}\,\ChurchNumeral{k}}{\ChurchNumeral{r+1}}.$$
Then
$$\LambdaInputSteps{p}{\LambdaSearchProgram{H}\,o\,\ChurchNumeral{n}}{\ChurchNumeral{j(p,n)}}.$$
Consequently, $\LambdaSearchProgram{H}$ is a Type-Two lambda realizer of $p\mapsto\Sequence{j(p,n)}{n\in\NN}$ on $D$.
Tests
after the successful candidate need not terminate.
\end{theorem*}

\begin{proof}[Proof]
Fix $p,n$ and abbreviate $G:=H\,o\,\ChurchNumeral{n}$ and $j:=j(p,n)$. The only possible free variable of $G$ is $o$.
Choose the kernel binders different from $o$ and set
$$S_k:=\bigl(\LambdaSearchKernel{G}\,\LambdaSearchKernel{G}\bigr)\ChurchNumeral{k}.$$
The two outer beta steps of the wrapper, followed by the beta step of the search term, produce $S_0$. Two beta steps
unfold the self-application at any candidate:
$$S_k\to_\beta^*
\LambdaZeroTest\,(G\ChurchNumeral{k})\,\ChurchNumeral{k}\,
\bigl((\LambdaSearchKernel{G}\,\LambdaSearchKernel{G})(\LambdaSucc\,\ChurchNumeral{k})\bigr).$$
Freshness of the binders preserves the test term and the duplicated kernel in these substitutions.

If $k<j$, reduce the test to the positive numeral supplied by the hypothesis. Zero testing selects the continuation, and
successor reduces its argument to $\ChurchNumeral{k+1}$. Thus
$$\LambdaInputSteps{p}{S_k}{S_{k+1}}\qquad(k<j).$$
At $k=j$, the test reduces to $\ChurchNumeral{0}$, so the other branch returns $\ChurchNumeral{j}$. It discards the
continuation without reducing it.

Starting from the successful case and working backwards through the finitely many preceding candidates proves that every
$S_k$ with $k\le j$ reduces to $\ChurchNumeral{j}$. In particular, this holds for $S_0$, including when $j=0$. All
concatenated reductions are finite. The wrapper is closed because $H$ and the search term are closed and both remaining
arguments are bound. Confluence excludes any other numeral output, giving the exact-output condition on $D$. Neither the
term nor the proof requires a uniform bound on $j(p,n)$ or a test for membership in $D$.
\end{proof}

\begin{corollary*}[\termdefineas{lambda least-witness search}{Least-witness search}]
Suppose that a closed $H$ returns $\ChurchNumeral{f(p,n,k)}$ on $o,\ChurchNumeral{n},\ChurchNumeral{k}$ for every $p\in
D$ and $n,k\in\NN$, where $f:D\times\NN^2\to\NN$. If for every $p,n$ some $k$ satisfies $f(p,n,k)=0$, then
$\LambdaSearchProgram{H}$ realizes
$$p\longmapsto\Sequence{\min\{k\in\NN:f(p,n,k)=0\}}{n\in\NN}.$$
\end{corollary*}

\begin{proof}[Proof]
The nonempty set of successful candidates has a least element. At every smaller candidate, the total numerical test
returns a nonzero natural number, hence a successor numeral. Apply the theorem to this least element.
\end{proof}

\begin{example*}[Finding the first zero of an input name]
Take
$$D:=\{p\in\BaireSpace:\exists k\in\NN\;p(k)=0\},\qquad
H:=\lambdaab{a}{\lambdaab{b}{\lambdaab{k}{ak}}}.$$
Then $\LambdaSearchProgram{H}$ realizes on $D$ the constant name whose every coordinate is $\min\{k:p(k)=0\}$.
\end{example*}

\begin{proof}[Proof]
Three beta steps and one query reduce $H\,o\,\ChurchNumeral{n}\,\ChurchNumeral{k}$ to $\ChurchNumeral{p(k)}$. Thus the
test is total, independently of $n$, and the definition of $D$ supplies a zero witness. Apply the corollary.
\end{proof}

\begin{mathmeta}
  \define{LambdaNonzeroSearch}
\end{mathmeta}

For detecting a nonzero digit, reverse the numerical answers of the test and put
$$H:=\lambdaab{a}{\lambdaab{b}{\lambdaab{k}{
\LambdaZeroTest\,(ak)\,\ChurchNumeral{1}\,\ChurchNumeral{0}}}},
\qquad \LambdaNonzeroSearch:=\LambdaSearchProgram{H}.$$
The coordinate argument $b$ is unused. Three beta steps, one query, and zero testing give
$$\LambdaInputSteps{p}{H\,o\,\ChurchNumeral{n}\,\ChurchNumeral{k}}{
\begin{cases}
\ChurchNumeral{1},&p(k)=0,\\
\ChurchNumeral{0},&p(k)\ne0.
\end{cases}}$$

\begin{proposition*}[\termdefineas{lambda nonzero search}{Exact domain of nonzero search}]
The term $\LambdaNonzeroSearch$ is closed. For every $p\in\BaireSpace$ and $n,m\in\NN$,
$$\bigl(\LambdaInputSteps{p}{\LambdaNonzeroSearch\,o\,\ChurchNumeral{n}}{\ChurchNumeral{m}}\bigr)
\iff p(m)\ne0\ \land\ (\forall k<m)\;p(k)=0.$$
Consequently, it produces a numeral exactly when $p$ has a nonzero digit, and that numeral gives the least such
coordinate.
\end{proposition*}

\begin{proof}[Proof]
If $j$ is the first nonzero coordinate, the displayed test returns a positive numeral before $j$ and zero at $j$. The
sequential-search theorem therefore gives output $\ChurchNumeral{j}$. Closedness follows from the definitions.

Suppose now that $p(k)=0$ for every $k$, but the program produces $\ChurchNumeral{m}$. By the finite-use argument in
§{sec:lambda-input-finite-use}, some $N$ bounds every queried coordinate in this finite reduction. Set
$j:=\max\{N,m+1\}$ and define
$$q(k):=\begin{cases}1,&k=j,\\p(k),&k\ne j.\end{cases}$$
Since $q$ agrees with $p$ below $N$, the same reduction with input $q$ produces $\ChurchNumeral{m}$. However, the first
nonzero coordinate of $q$ is $j$, so the preceding calculation also gives $\ChurchNumeral{j}$. Uniqueness of numeral
outputs forces $m=j$, contradicting $j>m$. Thus the all-zero name admits no numeral output.

Any name admitting a numeral output therefore has a first nonzero coordinate. The successful-search calculation and
output uniqueness identify that coordinate with the output. This proves both directions of the equivalence, including
when the first nonzero coordinate is zero.
\end{proof}

\begin{lemma*}[\termdefineas{Uniform search through finite trials}{Uniform search through finite trials}]
Suppose a finite oracle program, with oracle $p$, numerical parameter $a$, and stage $m$, always terminates and returns
either failure or a natural-number value. There is a primitive-recursive transformation of its code into a program which
returns the value at the first successful stage, and is undefined if no stage succeeds. The same transformed program
works for every $p$ and $a$.
\end{lemma*}

\begin{proof}[Proof]
Write $A$ for the given closed trial term, with failure encoded by zero and success with value $v$ encoded by $v+1$. For
fixed input variable $o$ and numerical parameter $a$, put
$$G:=\lambdaab{k}{\LambdaZeroTest\,(Aoak)\,\ChurchNumeral{1}\,\ChurchNumeral{0}},
\qquad F:=\lambdaab{k}{\LambdaPred(Aoak)}.$$
Use $\LambdaResultSearch\,G\,F$, abstracting $o,a$ to obtain one closed program. At the first successful stage, the test
is zero and the result function returns the predecessor of a positive numeral, hence the recorded value. Before that
stage the test is positive. If every stage fails, the no-output part of the result-search lemma excludes every numeral
output. The predecessor is needed only in the successful branch. All binders can be chosen fresh once in this finite
construction. Inserting the given syntax into this fixed expression and constructing its binders are primitive-recursive
operations on syntax codes.
\end{proof}

#### Universal evaluation with an input name {#sec:lambda-input-universal-evaluation}

\begin{mathmeta}
  \define{LambdaQueryInputCodeProgram,LambdaQueryOutputCandidate,LambdaQueryOutputSearch}
\end{mathmeta}

\begin{lemma*}[\termdefineas{input search with result function}{Search with an input name and a result function}]
Let $G,F$ have no free variables other than possibly $o$, and use the result-search term of §{sec:lambda-output-search},
with its internal binders distinct from $o$. If the test $G\ChurchNumeral{j}$ reduces with input $p$ to zero and every
earlier test reduces to a positive numeral, then
$$\LambdaInputSteps{p}{\LambdaResultSearch\,G\,F}{F\ChurchNumeral{j}}.$$
If every test reduces with input $p$ to a positive numeral, then $\LambdaResultSearch\,G\,F$ has no numeral output with
that input.
\end{lemma*}

\begin{proof}[Proof]
The two parameter substitutions and the two contractions unfolding each kernel remain valid because their binders avoid
the only possible free variable $o$. Put
$S_k:=(\LambdaResultSearchKernel{G}{F}\,\LambdaResultSearchKernel{G}{F})\ChurchNumeral{k}$. The first unfolding
contraction is a head step. A positive test selects the continuation, and successor gives $S_{k+1}$. A zero test selects
$F\ChurchNumeral{k}$; this branch also avoids capture. Backward induction from $j$ gives the first assertion. If every
test is positive, the stages $S_k$ satisfy the infinite-stage proposition in §{sec:lambda-input-head-exposure}. Finally,
confluence and the terminality of numerals transfer any putative numeral output of the outer search term to $S_0$,
giving a contradiction.
\end{proof}

Retain the indexed closed programs $P_e$ and their fixed named representatives from §{sec:lambda-program-input-codes}.
The initial term on numerical input $n$ is now $P_eo\ChurchNumeral{n}$. Its named syntax code is computed by the closed
term
$$\begin{aligned}
\LambdaQueryInputCodeProgram:=\lambdaab{e}{\lambdaab{n}{
 \LambdaTaggedCode{1}\,
 (\LambdaTaggedCode{1}\,(\LambdaProgramCode\,e)\,\ChurchNumeral{0})
 \, (\LambdaNumeralCodeProgram\,n)}}.
\end{aligned}$$
Here zero is the syntax code of $o=x_0$. Two applications of the application-code constructor, together with the
program-code and numeral-code programs, therefore give the required code by finite beta-reduction. The table checks
below still use named syntax codes and alpha-equivalence at joins.

Decode a candidate number $k$ as a proposed output $m$ and a certificate-search bound $s$. The closed candidate tester
is
$$\begin{aligned}
\LambdaQueryOutputCandidate:=\lambdaab{o}{\lambdaab{e}{\lambdaab{n}{\lambdaab{k}{
 \LambdaBoundedInputCheck\,o\,
 (\LambdaQueryInputCodeProgram\,e\,n)\\
 \qquad(\LambdaNumeralCodeProgram\,(\LambdaNumericProjection{1}\,k))
 \, (\LambdaNumericProjection{2}\,k)}}}}.
\end{aligned}$$
For every $p,e,n,k$, it returns one or zero according as the bounded test for the initial term and the proposed output
numeral succeeds or fails. The coding programs compute the two endpoints, and §{sec:lambda-input-check-programs} proves
the exact result of the bounded checker. Hence this is a total numerical test for each input name. A program returns $m$
if and only if some candidate with first component $m$ succeeds. Every successful candidate has the same first
component, by confluence of the original program's reductions.

Reverse the test answers and use the output projection only in the successful branch:
$$\begin{aligned}
T_q&:=\lambdaab{o}{\lambdaab{e}{\lambdaab{n}{\lambdaab{k}{
 \LambdaZeroTest\,(\LambdaQueryOutputCandidate\,o\,e\,n\,k)
 \,\ChurchNumeral{1}\,\ChurchNumeral{0}}}}},\\
\LambdaQueryOutputSearch&:=\lambdaab{o}{\lambdaab{e}{\lambdaab{n}{
 \LambdaResultSearch\,(T_q\,o\,e\,n)\,\LambdaNumericProjection{1}}}}.
\end{aligned}$$
All displayed variables are bound, so both terms are closed and work uniformly for every input name.

\begin{theorem*}[\termdefineas{exact input universal evaluation}{Exact universal evaluation with an input name}]
For every name $p$ and natural numbers $e,n,m$,
$$\begin{aligned}
&\LambdaInputSteps{p}{\LambdaQueryOutputSearch\,o\,\ChurchNumeral{e}\,\ChurchNumeral{n}}{\ChurchNumeral{m}}\\
&\qquad\Longleftrightarrow\quad
\LambdaInputSteps{p}{P_eo\ChurchNumeral{n}}{\ChurchNumeral{m}}.
\end{aligned}$$
Thus the two computations have the same numerical values and the same domain of numerical output, including when neither
produces a numeral.
\end{theorem*}

\begin{proof}[Proof]
If the indexed program returns $m$, finite-stage detection supplies a successful candidate with output component $m$.
Choose the least successful candidate $j$. The reversed test returns one at every earlier candidate and zero at $j$.
Search with a result function therefore reaches the first projection of $\ChurchNumeral{j}$, which is
$\ChurchNumeral{m}$ because all successful candidates have the same output component.

If the indexed program has no numeral output, every candidate fails. All reversed tests return one, so the no-output
assertion of the preceding search lemma excludes every numeral from the search body. The outer parameter contractions
cannot create an additional output: confluence would carry any such numeral output to that same body.

Finally, when the indexed program has an output, the first argument supplies it from the evaluator as well, and
uniqueness excludes a different numeral. Combined with the no-output case, this proves the equivalence for all inputs
without a termination assumption. The same single closed term is used throughout; no finite description of $p$ is
assumed.
\end{proof}

#### Finite computation trials {#sec:tte-finite-trials}

\begin{mathmeta}
  \define{LambdaFiniteTrial}
  \forward{LambdaResultSearch,LambdaQueryOutputSearch,LambdaUniformInterpreter,LambdaIndexSpecialization}
  \vars{e,k,m,n,s}{Nat}
  \vars{p}{Name}
\end{mathmeta}

\begin{lemma*}[\termdefineas{Uniform finite-table simulation}{Uniform finite lambda trials}]
There is one closed lambda term $\LambdaFiniteTrial$ that, for every input name $p$ and natural numbers $e,n,k$, returns
a numeral on input $o\ChurchNumeral{e}\ChurchNumeral{n}\ChurchNumeral{k}$. Zero records failure; $m+1$ records success
with value $m$. Every recorded value is an output of the indexed program $P_e$ on input $n$ with name $p$, and every
such output is recorded at some stage $k$. The result of each trial depends only on a finite prefix of $p$ whose length
is determined by $k$.
\end{lemma*}

\begin{proof}[Proof]
Decode $k=\NatPair{m}{s}$. A finite reduction certificate consists of a finite answer table and a finite list of
beta/query steps. Inspect all certificate codes below $s$. For each code, check the recorded steps, alpha-equivalence at
their joins, the initial term $P_eo\ChurchNumeral{n}$, the final numeral $\ChurchNumeral{m}$, and agreement of every
recorded answer with $p$. These are finite checks on lambda syntax and finite lists. Their recursions, numerical
comparisons and input queries give a single closed lambda term $C$ returning one exactly when some certificate is
accepted, and zero otherwise. The constructions in §{sec:lambda-input-check-programs} and
§{sec:lambda-input-universal-evaluation} give this term explicitly. Put
$$\begin{aligned}
\LambdaFiniteTrial:=\lambdaab{o}{\lambdaab{e}{\lambdaab{n}{\lambdaab{k}{
 \LambdaZeroTest\,(Coenk)\,\ChurchNumeral{0}\,
 (\LambdaSucc(\LambdaNumericProjection{1}\,k))}}}}.
\end{aligned}$$
Thus a rejected candidate returns zero, and an accepted candidate returns $m+1$. Every check terminates; the original
program need not terminate.

An accepted certificate gives an actual finite beta/query reduction because all its answers agree with $p$. Conversely,
every numeral output has a finite reduction, hence a certificate with a finite code. Some bound $s$ includes it.
Finally, only finitely many answer tables occur below $s$; the maximum of their queried addresses, plus one, bounds the
prefix needed to determine every test result; take zero if there are no queries. This bound depends on $s$, hence on
$k$, before the name is supplied. Failure at one stage asserts neither divergence nor nonmembership.
\end{proof}

#### Packing inputs and specializing program indices {#sec:lambda-program-specialization}

\begin{mathmeta}
  \define{LambdaUniformInterpreter,LambdaIndexSpecialization,LambdaSpecializationCode,LambdaSpecializationCodeProgram}
  \vars{e,u}{Nat}
  \vars{n}{Nat}
\end{mathmeta}

The evaluator just constructed takes its index and numerical input separately. The single-input convention of
§{sec:type-two-lambda-realizers} is recovered by the closed term
$$\LambdaUniformInterpreter:=\lambdaab{o}{\lambdaab{z}{
 \LambdaQueryOutputSearch\,o\,(\LambdaNumericProjection{1}\,z)\,
 (\LambdaNumericProjection{2}\,z)}}.$$
For a closed term $P$ with its input name and first numerical argument supplied in that order, define
$$\LambdaIndexSpecialization{P}{e}:=
 \lambdaab{x_{40}}{P\,x_{40}\,\ChurchNumeral{e}}.$$
Since $P$ is closed, this fixed binder captures no free occurrence in $P$. The argument $e$ is fixed in the syntax,
while the input name and remaining numerical input are still supplied at run time.

\begin{theorem*}[\termdefineas{Uniform lambda interpretation and specialization}{Uniform lambda interpretation and
specialization}]
The terms $\LambdaUniformInterpreter$ and $\LambdaIndexSpecialization{\LambdaQueryOutputSearch}{e}$ are closed. For
every $p,e,n,m$,
$$\begin{aligned}
&\LambdaInputSteps{p}{\LambdaUniformInterpreter\,o\,\ChurchNumeral{\NatPair{e}{n}}}{\ChurchNumeral{m}}\\
&\quad\Longleftrightarrow\LambdaInputSteps{p}{P_eo\ChurchNumeral{n}}{\ChurchNumeral{m}}\\
&\quad\Longleftrightarrow
 \LambdaInputSteps{p}{\LambdaIndexSpecialization{\LambdaQueryOutputSearch}{e}\,o\,\ChurchNumeral{n}}{\ChurchNumeral{m}}.
\end{aligned}$$
Thus the domains also agree, with no termination assumption.
\end{theorem*}

\begin{proof}[Proof]
The outer abstractions bind every free variable. For the paired input, two beta contractions and the two projection
computations reach $\LambdaQueryOutputSearch\,o\,\ChurchNumeral{e}\,\ChurchNumeral{n}$. For the specialized term, one
beta contraction reaches this same term. Each reduction can be prepended to an evaluator output. Conversely, if either
starting term has a numeral output, confluence gives a common reduct of that numeral and the evaluator term. A numeral
admits no further beta/query step, so the evaluator reduces to that very numeral. The exact universal-evaluation theorem
now gives both equivalences, including the case of no numeral output.
\end{proof}

We next compute the syntax code of the specialized program. For the fixed named representatives, set
$$\begin{aligned}
\LambdaSpecializationCode{u}{e}:=
 3\NatPair{40}{3\NatPair{3\NatPair{u}{120}+1}{\LambdaSyntaxCode{\ChurchNumeral{e}}}+1}+2.
\end{aligned}$$
Here $120$ is the code of $x_{40}$. The inner two application codes attach this variable and the numeral to the term
coded by $u$; the final abstraction binds $x_{40}$. This formula is defined for every pair of natural numbers, even when
the decoded term is open.

The numerical formula is implemented by the closed lambda term
$$\begin{aligned}
\LambdaSpecializationCodeProgram:=\lambdaab{u}{\lambdaab{e}{
 \LambdaTaggedCode{2}\,\ChurchNumeral{40}\,\bigl(\\
 \qquad\LambdaTaggedCode{1}\,
   (\LambdaTaggedCode{1}\,u\,\ChurchNumeral{120})\,
   (\LambdaNumeralCodeProgram\,e)\bigr)}}.
\end{aligned}$$

\begin{proposition*}[\termdefineas{Lambda specialization on syntax codes}{Specialization on syntax codes}]
For all $u,e\in\NN$,
$$\LambdaSpecializationCodeProgram\,\ChurchNumeral{u}\,\ChurchNumeral{e}
 \to_\beta^*\ChurchNumeral{\LambdaSpecializationCode{u}{e}}.$$
The decoded result is exactly the named term obtained by applying the term decoded from $u$ to $x_{40}$ and
$\ChurchNumeral{e}$ and then abstracting $x_{40}$. If the original term is closed, the result is closed and represents
its specialization. Moreover, the function $\Pair{u}{e}\mapsto\LambdaSpecializationCode{u}{e}$ is primitive recursive.
\end{proposition*}

\begin{proof}[Proof]
Two beta contractions supply the arguments. Compute the numeral code, then the two application codes, and finally the
abstraction code. The code-decoding identities identify the result with the stated named term for every $u$. On
alpha-classes this term is $\LambdaIndexSpecialization{P}{e}$ when $P$ is the decoded closed term; its only additional
variable is bound by the outer abstraction.

For primitive recursiveness, let $c_n$ be the code of the body of the fixed Church numeral before its two abstractions.
Then
$$c_0=6,\qquad c_{n+1}=3\NatPair{3}{c_n}+1,
\qquad\LambdaSyntaxCode{\ChurchNumeral{n}}=3\NatPair{1}{3\NatPair{2}{c_n}+2}+2.$$
Primitive recursion computes $c_n$. Pairing, addition and multiplication then compute the numeral code and the displayed
specialization formula. This proves the primitive-recursion claim without assuming an unspecified compiler.
\end{proof}

Choose one named representative of $\LambdaQueryOutputSearch$ and fix its code $u$ once. The single primitive-recursive
map $e\mapsto\LambdaSpecializationCode{u}{e}$ then gives, for every input name, a program with exactly the same partial
numerical evaluation as $P_e$. Its code is computed by $\LambdaSpecializationCodeProgram\,\ChurchNumeral{u}$, which is
closed. Thus the transformation is fixed before the input name and the program index are supplied.

### Self-reference on program indices {#sec:lambda-index-recursion}

\begin{mathmeta}
  \vars{a,i,n,v,w}{Nat}
  \vars{f}{Fun(Nat,Nat)}
\end{mathmeta}

The specialization formula can insert a program's own index without executing that program. We give the construction
explicitly. In the following term, use the fixed variable names $n=x_{80}$ and $x=x_{81}$. For any closed term $H$, put
\begin{mathmeta}
  \define{LambdaDiagonalTerm}
\end{mathmeta}
$$\LambdaDiagonalTerm{H}:=\lambdaab{n}{\lambdaab{x}{
 H(\LambdaSpecializationCodeProgram\,x\,x)n}}.$$
Choose a named representative of this closed term, let $d$ be its syntax code, and set
$$e:=\LambdaSpecializationCode{d}{d}.$$
These are finite syntax constructions; no test of termination is involved.

\begin{lemma*}[\termdefineas{lambda index self-reference}{Self-reference by specialization}]
The index $e$ just constructed satisfies
$$P_eN\to_\beta^*H\ChurchNumeral{e}N$$
for every term $N$ in which $x_{81}$ does not occur free. In particular, it works for every numeral and for the
input-function variable $o=x_0$.
\end{lemma*}

\begin{proof}[Proof]
The specialization-code identity gives $P_e=\LambdaIndexSpecialization{\LambdaDiagonalTerm{H}}{d}$.
One beta contraction supplies $N$, and two more supply $N$ and $\ChurchNumeral{d}$ to the diagonal term. Since
$x_{81}$ is not free in $N$, this yields
$$H(\LambdaSpecializationCodeProgram\,\ChurchNumeral{d}\,\ChurchNumeral{d})N.$$
The specialization-code program reduces its inner argument to $\ChurchNumeral{e}$. Every step is a beta reduction,
and the code was fixed before $N$ was supplied.
\end{proof}

\begin{proposition*}[\termdefineas{uniform lambda self-reference indices}{Uniform self-reference indices}]
There is a total numerical function $e$, computed by a closed lambda term, with the following property.
Whenever $u$ is the syntax code of a closed term, for every $N$ in which $x_{81}$ does not occur free,
$$P_{e(u)}N\to_\beta^*P_u\ChurchNumeral{e(u)}N.$$
The map $e$ is defined on all natural numbers; the closedness hypothesis concerns this reduction identity.
\end{proposition*}

\begin{proof}[Proof]
Fix a named representative $S$ of $\LambdaSpecializationCodeProgram$ once. Write
$$A(v,w):=3\NatPair{v}{w}+1,\qquad L(i,v):=3\NatPair{i}{v}+2$$
for the numerical application and abstraction constructors, and put
$$\begin{aligned}
k&:=A\bigl(A(\LambdaSyntaxCode{S},243),243\bigr),\\
d(u)&:=L\bigl(80,L(81,A(A(u,k),240))\bigr),\\
e(u)&:=\LambdaSpecializationCode{d(u)}{d(u)}.
\end{aligned}$$
The constants $243$ and $240$ are the variable codes of $x_{81}$ and $x_{80}$, respectively.
Thus $d(u)$ is the code of the displayed diagonal term with the decoded input term inserted for $H$.
Application-code construction, abstraction-code construction and specialization compute $e(u)$ by beta reduction
for every input. If the decoded term is closed, the preceding self-reference proof applies to this very
representative and gives the asserted reduction. The representative $S$ is fixed before $u$ is supplied.
\end{proof}

\begin{lemma*}[\termdefineas{uniform numerical parameter indices}{Uniform numerical parameter indices}]
There is a total computable map $\Pair{u}{a}\mapsto p(u,a)$ such that, whenever $u$ is the syntax code of a closed term,
$p(u,a)$ is also the syntax code of a closed term and
$$P_{p(u,a)}=\bigl(\lambdaab{v}{\lambdaab{n}{P_u(\LambdaNumericPair\,v\,n)}}\bigr)\ChurchNumeral{a}.$$
In particular, if $P_u$ computes a total numerical function $f$, then $P_{p(u,a)}$ computes
$$n\longmapsto f\bigl(\NatPair{a}{n}\bigr).$$
The index map is total even when the supplied program is partial.
\end{lemma*}

\begin{proof}[Proof]
Fix a named representative of $\LambdaNumericPair$ before the inputs are supplied. Abstraction and application
of syntax codes give the code $c(u)$ of $\lambdaab{v}{\lambdaab{n}{P_u(\LambdaNumericPair\,v\,n)}}$,
with the decoded input syntax inserted literally. If $\nu(a)$ is the code of $\ChurchNumeral{a}$, set
$$p(u,a):=3\NatPair{c(u)}{\nu(a)}+1.$$
Each code operation is computed by a closed numerical term on every input. For closed input syntax, the
constructed term is closed and its alpha-class is the displayed application. Applying it to $\ChurchNumeral{n}$
and performing the two beta contractions and numerical pairing gives
$$P_{p(u,a)}\ChurchNumeral{n}\to_\beta^*P_u\ChurchNumeral{\NatPair{a}{n}}.$$
The computation of $f$ gives the asserted output. Constructing the index itself never runs $P_u$.
\end{proof}

\begin{corollary*}[\termdefineas{uniform self-indexed numerical families}{Uniform self-indexed numerical families}]
There is a total computable map $u\mapsto q(u)$ such that, whenever $u$ is the syntax code of a closed
term computing a total numerical function $f$, the program $P_{q(u)}$ computes
$$a\longmapsto f\bigl(\NatPair{q(u)}{a}\bigr).$$
\end{corollary*}

\begin{proof}[Proof]
Fix a representative of numerical pairing. The syntax constructors compute from $u$ the code $c(u)$ of
$$\lambdaab{v}{\lambdaab{a}{P_u(\LambdaNumericPair\,v\,a)}}.$$
Here the syntax decoded from the input is inserted literally; when it is closed, the displayed expression
is its alpha-class. Set $q(u):=e(c(u))$. The preceding proposition gives the self-reference reduction,
and numerical pairing followed by the computation of $f$ gives the required numeral output.
Computing $c(u)$ and $q(u)$ never runs $P_u$.
\end{proof}

\begin{theorem*}[\termdefineas{lambda index recursion theorem}{Recursion theorem for lambda indices}]
Let $f:\NN\to\NN$ be total and computed by a closed lambda term $F$. There is an index $e$ such that
$$\varphi_e(n)\simeq\varphi_{f(e)}(n)$$
for every $n$. Equality here includes undefined values.
\end{theorem*}

\begin{proof}[Proof]
Use the self-reference lemma with the closed term
$$H:=\lambdaab{z}{\LambdaOutputSearch(Fz)}.$$
It gives an index $e$ for which
$$P_e\ChurchNumeral{n}\to_\beta^*
 \LambdaOutputSearch(F\ChurchNumeral{e})\ChurchNumeral{n}
 \to_\beta^*\LambdaOutputSearch\,\ChurchNumeral{f(e)}\,\ChurchNumeral{n}.$$
The last reduction uses totality of $f$. Exact universal evaluation identifies the numeral outputs of the last term
with those of $P_{f(e)}\ChurchNumeral{n}$. These reductions can be prepended to any such output. Conversely,
confluence and normality of numerals imply that any numeral output of the starting term is also an output of the last
term. Thus all values and the domains agree.
\end{proof}

\begin{theorem*}[\termdefineas{lambda uniform input recursion theorem}{Recursion with an unchanged input function}]
Under the same hypothesis on $f$, there is an index $e$, independent of the input function $p$, such that for every
$p,n,m$,
$$\LambdaInputSteps{p}{P_eo\ChurchNumeral{n}}{\ChurchNumeral{m}}
 \quad\Longleftrightarrow\quad
 \LambdaInputSteps{p}{P_{f(e)}o\ChurchNumeral{n}}{\ChurchNumeral{m}}.$$
The transformer $f$ itself uses no input function. The programs it transforms may query $p$.
\end{theorem*}

\begin{proof}[Proof]
Now use the closed term
$$H:=\lambdaab{z}{\lambdaab{o}{\LambdaQueryOutputSearch\,o\,(Fz)}}.$$
The self-reference construction fixes $e$ before $p$ is supplied. Apply its reduction to the argument $o=x_0$, then
supply $\ChurchNumeral{n}$. Beta reduction and the computation of $F\ChurchNumeral{e}$ give
$$P_eo\ChurchNumeral{n}\to_\beta^*
 \LambdaQueryOutputSearch\,o\,\ChurchNumeral{f(e)}\,\ChurchNumeral{n}.$$
The exact evaluator theorem with input queries and confluence give both directions, just as above. Every query uses
the same $p$ on both sides, and equality also holds when neither side has a numeral output.
\end{proof}

The following construction concerns finite named lambda syntax. It does not interpret a second programming language. Fix
named representatives of the numerical pairing, zero-test and predecessor terms. Fix also closed terms $E,L,R,A$, whose
roles may be an evaluator, two name projections and a reassociation program. Their representatives and codes are chosen

For named terms $P,Q$, use the templates
$$\begin{aligned}
C_{P,Q}&:=\lambdaab{x_1}{\lambdaab{x_2}{P\,(Qx_1)\,x_2}},\\
\LambdaPairOutputs{P}{Q}&:=\lambdaab{x_1}{\lambdaab{x_2}{
\LambdaNumericPair\,(Px_1x_2)\,(Qx_1x_2)}},\\
\LambdaNamePrefix{e}&:=\lambdaab{x_1}{\lambdaab{x_2}{
\LambdaZeroTest\,x_2\,\ChurchNumeral{e}\,
\bigl(x_1(\LambdaPred\,x_2)\bigr)}}.
\end{aligned}$$
When the inserted terms are closed, these templates are closed too. Their alpha-classes are the same composition,
pairing and prefixing terms used for name computations.

\begin{proposition*}[\termdefineas{Lambda function-space code transformations}{Function-space transformations on
syntax codes}]
The following operations on codes of the displayed named terms are primitive recursive and are computed by closed lambda
terms:
$$\begin{aligned}
e&\longmapsto\LambdaSyntaxCode{\LambdaNamePrefix{e}},\\
\LambdaSyntaxCode{P}&\longmapsto\LambdaSyntaxCode{C_{P,A}},\\
\LambdaSyntaxCode{Q}&\longmapsto
\LambdaSyntaxCode{C_{E,\LambdaPairOutputs{C_{Q,L}}{R}}}.
\end{aligned}$$
The decoded outputs are exactly the displayed named terms. In the last two lines, closed input syntax gives closed
output syntax. There are also transformations defined on every enumeration index: first replace the indexed program by
its closed specialization of the universal evaluator, then apply the corresponding syntax transformation. This
replacement preserves every numeral output and absence of numeral outputs for every input name and numerical input.
\end{proposition*}

\begin{proof}[Proof]
The code constructors for application and abstraction are, respectively,
$$ \Pair{a}{b}\longmapsto3\NatPair{a}{b}+1,
\qquad \Pair{i}{a}\longmapsto3\NatPair{i}{a}+2.$$
They are primitive recursive and are computed by the closed terms $\LambdaTaggedCode{1}$ and $\LambdaTaggedCode{2}$. The
variable codes of $x_1,x_2$ are $3,6$. The map $e\mapsto\LambdaSyntaxCode{\ChurchNumeral{e}}$ is primitive recursive and
is computed by $\LambdaNumeralCodeProgram$, by §{sec:lambda-program-specialization}. For a composition template, attach
$x_1$ to the inner program, apply the outer program to that result and $x_2$, then add the two abstractions. For a
pairing template, apply each inserted program to $x_1,x_2$, apply numerical pairing to those two results, then add the
abstractions. For a prefix template, insert the numeral code, form the zero test and predecessor-query branch, then add
the abstractions. Applying these finite recipes to the nested uncurrying template gives the third transformation.

For completeness, these arithmetic compositions have actual lambda implementations. If closed terms $F,G$ compute two
numerical functions and a closed term $B$ computes a binary operation, the term
$$\lambdaab{x}{B\,(Fx)\,(Gx)}$$
computes their pointwise combination: one beta step supplies the input, reduce the two inner computations, then reduce
the application of $B$. Unary composition uses $\lambdaab{x}{F(Gx)}$ in the same way. Constants and the identity have
closed numerical implementations. Iterating these constructions with the code constructors and numeral-code term gives a
single closed program for each recipe. Induction through the named syntax, using the coding and decoding identities,
identifies its output with the exact template code. Closedness follows because the inserted program terms have no free
variables and the templates bind their displayed variables. This verifies both the code-level construction and the
lambda program that performs it.

Finally, fix the code $u$ of a named representative of $\LambdaQueryOutputSearch$. On any enumeration index $e$, first
compute $\LambdaSpecializationCode{u}{e}$. By §{sec:lambda-program-specialization}, it decodes to a closed term with
exactly the same partial numerical behavior as $P_e$, even if the raw syntax decoded from $e$ is open. The preceding
transformations therefore apply to this closed code. Composition preserves primitive recursiveness and the closed lambda
implementations. No answers from an input name are placed in these finite codes.
\end{proof}

### A fixed reader for continuous maps {#sec:lambda-continuous-reader}

\begin{mathmeta}
  \define{LambdaNameAccessor,LambdaCylinderPrefix,LambdaCylinderQuery,LambdaCylinderTest,LambdaContinuousReader}
  \vars{i,j,k,m,n}{Nat}
  \vars{s}{Seq(Nat)}
  \vars{r,p,q,w}{Name}
  \vars{N,v}{Nat}
\end{mathmeta}

Join two names pointwise by $w(j):=\NatPair{r(j)}{p(j)}$. The left component $r$ will describe a continuous map, and the
right component $p$ will be its input. To access either component, put $I:=\lambdaab{x}{x}$ and
$$\LambdaNameAccessor{i}{A}:=
 (\lambdaab{a}{\lambdaab{j}{\LambdaNumericProjection{i}\,(Iaj)}})A
 \qquad(i=1,2).$$
The outer binders are fresh for $A$. On input $w$, the term $\LambdaNameAccessor{1}{o}\,\ChurchNumeral{j}$ returns
$\ChurchNumeral{r(j)}$, and the second accessor returns $\ChurchNumeral{p(j)}$. This follows by the two outer beta
steps, the identity reduction, one query and numerical projection.

At stage $k=\NatPair{N}{v}$, read the prefix of length $N$ and ask whether it certifies output $v$ at coordinate $n$.
Encode the triple consisting of a coordinate, a finite sequence and a value by
$\NatPair{n}{\NatPair{\LambdaListCode{s}}{v}}$. The corresponding open terms are
$$\begin{aligned}
\LambdaCylinderPrefix{A}{K}&:=\LambdaInputPrefix\,
 (\LambdaNameAccessor{2}{A})\,(\LambdaNumericProjection{1}\,K),\\
\LambdaCylinderQuery{A}{B}{K}&:=\LambdaNameAccessor{1}{A}\,\bigl(
 \LambdaNumericPair\,B\,(
 \LambdaNumericPair\,\LambdaCylinderPrefix{A}{K}\,
 (\LambdaNumericProjection{2}\,K))\bigr).
\end{aligned}$$
Here $B$ in the term expression is the argument for the output coordinate; the stage projections determine the prefix
length and candidate value. The query returns the certificate name's actual digit, which may be any natural number.

Reverse the zero/nonzero test and use the second stage projection as the result function:
$$\begin{aligned}
\LambdaCylinderTest{A}{B}&:=\lambdaab{k}{\LambdaZeroTest\,
 \LambdaCylinderQuery{A}{B}{k}\,\ChurchNumeral{1}\,\ChurchNumeral{0}},\\
\LambdaContinuousReader&:=\lambdaab{a}{\lambdaab{n}{
 \LambdaResultSearch\,\LambdaCylinderTest{a}{n}\,\LambdaNumericProjection{2}}}.
\end{aligned}$$
Expand all abbreviations before binding their parameters, choosing the internal binders fresh. This defines one closed
finite lambda term, with no dependence on the domain or the map to be represented.

\begin{lemma*}[\termdefineas{lambda cylinder certificate reader}{Lambda reader for cylinder certificates}]
For arbitrary names $r,p$, put $w(j):=\NatPair{r(j)}{p(j)}$. At stage $k=\NatPair{N}{v}$ the term
$\LambdaCylinderQuery{o}{\ChurchNumeral{n}}{\ChurchNumeral{k}}$ returns
$$\ChurchNumeral{r(\NatPair{n}{\NatPair{\LambdaListCode{\restrict{p}{N}}}{v}})}.$$
Every trial terminates. If some trial returns a nonzero value, $\LambdaContinuousReader\,o\,\ChurchNumeral{n}$ returns
the candidate value at the least such stage and no other numeral. If no trial returns a nonzero value, the reader has no
numeral output.
\end{lemma*}

\begin{proof}[Proof]
The stage projections give the length and candidate value. Apply the finite-prefix proposition with the second accessor
to obtain the list code, then use numerical pairing twice and query the first accessor. Every component computation
terminates on every name. The reversed test therefore returns zero exactly at successful stages and one otherwise. At
the least success, the search lemma with a result function reaches the second projection of that stage, which returns
its candidate value. Confluence excludes a different numeral output. If there is no success, every reversed test returns
one; the no-output part of the same search lemma excludes all numeral outputs. The two outer beta contractions of the
reader preserve this conclusion by confluence.
\end{proof}

For a finite sequence $s$, write $\cyl{s}$ for the set of all names beginning with $s$. These prefix cylinders form a
basis for the product topology on Baire space.

\begin{theorem*}[\termdefineas{lambda coding of continuous maps}{Coding continuous maps by a fixed lambda reader}]
For every subset $D\IncludedIn\BaireSpace$ and continuous map $F:D\to\BaireSpace$, there is a name $r$ such that, for
$w(j):=\NatPair{r(j)}{p(j)}$, every $p\in D$ and $n,m\in\NN$ satisfy
$$\LambdaInputSteps{w}{\LambdaContinuousReader\,o\,\ChurchNumeral{n}}{\ChurchNumeral{m}}
 \quad\Longleftrightarrow\quad m=F(p)(n).$$
Conversely, a map on $D$ computed by a lambda term with any fixed auxiliary name is continuous on $D$. No openness or
effective description of $D$ is required.
\end{theorem*}

\begin{proof}[Proof]
Let $r$ have value one at the code of $\Tuple{n,s,v}$ exactly when $F(q)(n)=v$ for all $q\in D\cap\cyl{s}$, and zero
otherwise. Pairing and list coding are bijective, so this specifies a name on all coordinates. This name need not be
computable. On valid input $p$, every successful trial gives the correct value because $p$ lies in the cylinder of its
own prefix. Continuity of the coordinate map into discrete $\NN$ makes its fiber through $p$ open in $D$. Write this
fiber as $D\cap U$ with $U$ open in Baire space, and choose a prefix cylinder containing $p$ and contained in $U$. Its
length, together with $F(p)(n)$, gives a successful trial. The reader lemma now proves termination and the exact output
identity. Certificates for cylinders disjoint from $D$ do not affect valid inputs.

For the converse, a terminating computation uses only finitely many digits of the joined name. Fixing the auxiliary name
and varying the input within a sufficiently small cylinder preserves that computation. Uniqueness of numeral outputs
forces the coordinate of the computed map to remain constant there, relative to $D$. Each coordinate map is therefore
continuous, and so is the map into Baire space.
\end{proof}

### Represented spaces and TTE {#sec:lambda-tte}

A \termuse{represented space} is a set $X$ together with a partial surjection
$\PartialFunctionMap{\delta_X}{\BaireSpace}{X}$. A name of $x$ is a point $p\in\DomainOf{\delta_X}$ with
$\delta_X(p)=x$. A point $x$ is \termdefineas{computable point in represented space}{computable} if it has a computable
name.

For representations $\delta_X,\delta_Y$, a partial name map $\PartialFunctionMap{F}{\BaireSpace}{\BaireSpace}$ realizes
$f:X\to Y$ when its domain contains $\DomainOf{\delta_X}$, its values there belong to $\DomainOf{\delta_Y}$, and
$$\delta_Y(F(p))=f(\delta_X(p))\qquad(p\in\DomainOf{\delta_X}).$$
The function $f$ is \termdefineas{computable function between represented spaces}{computable} if such an $F$ has a
Type-Two lambda realizer. Thus $F$ is the map between names, and the closed lambda term is the program computing it. One
program must work for every name of every input point.

For Polish spaces with a chosen computable metric presentation, the representation $\rho_X$ used in
§{sec:cauchy-representation-admissibility} takes a name to the
limit of a fast Cauchy sequence in a fixed computable dense set. Thus a computable real is a real with a computable fast
Cauchy name, and a computable function between Polish spaces is one whose action on such names is computed by a lambda
realizer with the input name as a function argument.

This is the external TTE formulation. §{sec:effective-topos} instead uses natural-number realizers.
A TTE realizer induces a recursive transformation of indices for computable names, hence a morphism
between computable-point assemblies as in §{sec:inside-effective-topos}. This translation does not
identify arbitrary external names with natural-number indices.
